# Схема базы данных

Десять миграций под PostgreSQL 16+. Проверены накатом и откатом на чистой базе:
66 таблиц, 162 индекса, 33 enum-типа, 46 check-констрейнтов, 2 exclude-констрейнта.

## Зависимости

| Расширение | Зачем |
| --- | --- |
| `btree_gist` | EXCLUDE-констрейнты на слоты полей и периоды подписок |
| `postgis` | гео-поиск полей и определение дублей в радиусе |
| `unaccent` | снятие диакритики при нормализации |
| `citext` | регистронезависимый email |

Если на хостинге нет PostGIS — замените `geography(Point, 4326)` в `0005_pitches.sql`
на пару `double precision`, а `nearby_pitches()` на bounding box по широте и долготе.
Остальные девять миграций от PostGIS не зависят.

```

0008_economy.sql         очки, кредиты, подписки, косметика, достижения, прогнозы
```

Накат через goose:

```
goose -dir ./migrations postgres "$DATABASE_URL" up
```

## Что защищено на уровне базы, а не кода

Это главная ценность схемы: перечисленное ниже нельзя сломать багом в приложении
или гонкой двух одновременных запросов.

| Правило | Механизм |
| --- | --- |
| Два матча на одном поле в пересекающееся время | `EXCLUDE USING gist` + зазор 10 минут после свистка |
| Отменённый матч освобождает слот | предикат `WHERE status IN (...)` в том же констрейнте |
| Дворовая коробка не блокирует слот | флаг `blocks_pitch` в предикате |
| Одинаковые названия команд в одном городе | уникальный индекс по `(city_id, name_normalized)` |
| Клон названия латиницей («MOCKBA») | `normalize_text()` схлопывает гомоглифы **до** `lower()` |
| Один капитан — одна команда в городе | уникальный индекс по `(captain_id, city_id)` |
| Платный матч без суммы и бесплатный с суммой | два взаимных check-констрейнта |
| Прогнозы за купленную валюту | `CHECK (stake_kind = 'points')` — механика физически не может стать азартной |
| Голос за себя как за лучшего игрока | `CHECK (voter_id <> nominee_id)` |
| Публичная метка неплательщика от одного капитана | `CHECK (NOT is_public OR distinct_markers >= 2)` |
| Больше трёх снятых броней позиции | триггер `position_reservations_revoke_limit` |
| Возрастной порог команды ниже 14 | `CHECK (min_age >= 14)` |
| Изменение или удаление записи аудит-лога | триггер, который всегда бросает исключение |
| Две пересекающиеся подписки одного тира | `EXCLUDE` по `(user_id, tier, период)` |

## Решения, которые стоит знать

**Деньги.** Платформа не принимает и не хранит оплату аренды. `matches.rent_total_minor`
и `match_participants.share_minor` — справочный расчёт, `payment_notes` — заметки капитана.
Все суммы в минорных единицах (`bigint`), валюта берётся из страны города и пишется
в каждую запись матча: если валюта страны когда-нибудь сменится, старые матчи не должны
пересчитаться задним числом.

**Возраст.** Хранится дата рождения, возраст считается функцией `age_years()` на нужную дату.
Никакого поля `is_minor`: оно должно переключаться само в день восемнадцатилетия.
Пороги живут в `countries.min_signup_age` и `countries.age_of_majority` — в сиде заполнена
только Россия (14 и 18), для остальных стран числа нужно уточнять у юриста.

**Роли.** `role_assignments (user_id, role, scope_type, scope_id)`, а не колонка в `users`.
Без этого первая же ситуация «капитан в одной команде, игрок в другой» ломает модель.

**Статистика.** Считается в снапшоты (`*_daily`, `reliability_snapshots`) ночным пересчётом.
Агрегат по всей истории на каждый открытый экран — первое, что ляжет при росте.
`player_stats_daily.diversity_weight` понижает вес статистики, если последние матчи
сыграны с одними и теми же людьми: это защита не от выдуманных голов, а от выдуманных матчей.

**Незакрытый протокол.** Через 72 часа матч уходит в `expired` и не учитывается нигде —
ни в статистике, ни в надёжности, ни в паспорте команды. Команда, которой статистика
не нужна, должна мочь пользоваться приложением только ради сбора людей.

## Что осталось за пределами схемы

Турнирные сетки (`competitions` есть, генерация пар — нет), расчёт Elo, конкретные формулы
надёжности и diversity_weight, тексты уведомлений. Это логика приложения, а не структура данных.
