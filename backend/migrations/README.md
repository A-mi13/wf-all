# Схема базы данных

Миграции под PostgreSQL 18 (sqlc разбирает грамматику 17 — синтаксис 18 в SQL не
использовать). Первые десять проверены накатом и откатом на чистой базе:
66 таблиц, 162 индекса, 33 enum-типа, 46 check-констрейнтов, 2 exclude-констрейнта.

## Зависимости

| Расширение | Зачем |
| --- | --- |
| `btree_gist` | EXCLUDE-констрейнты на слоты полей и периоды подписок |
| `postgis` | гео-поиск полей и определение дублей в радиусе (`0005`); точки городов и мест GeoNames, ближайший город (`0019`) |
| `unaccent` | снятие диакритики при нормализации |
| `citext` | регистронезависимый email |

PostGIS обязателен двум миграциям: `0005_pitches.sql` (поиск полей рядом, `nearby_pitches()`) и
`0019_geo.sql` (точки городов и мест GeoNames, ближайший город и «накрывающее» место — GiST и
расстояние по сфере, в том числе у антимеридиана). Без PostGIS обе пришлось бы переписать на пару
`double precision` и bounding box. Остальные миграции от PostGIS не зависят.

## Порядок

```
0001_platform.sql        расширения, нормализация, аудит-лог, outbox, идемпотентность
0002_geo.sql             страны → регионы → города → районы
0003_identity.sql        пользователи, сессии, роли со скоупом, заявки на капитанство
0004_teams.sql           команды, составы, передача капитанства
0005_pitches.sql         поля и модерация
0006_matches.sql         матчи, слоты, протоколы, вызовы, турниры
0007_reputation.sql      надёжность, паспорт команды, метки расчётов
0008_economy.sql         очки, кредиты, подписки, косметика, достижения, прогнозы
0009_moderation_notifications.sql  жалобы, санкции, уведомления, реклама
0010_seed.sql            Россия, Ставрополь, Михайловск, фича-флаги, достижения
0011–0016_river_v2..v7.sql  схема очереди River, по файлу на версию (v1 — таблица версий River `river_migration` — не нужна и не создаётся: версии наших миграций River ведёт goose, `0014` отсутствие таблицы терпит; v8 — пустая для Postgres; страж — TestRiverMigrationLineCovered)
0017_platform_events.sql события: outbox с конвертом (UUIDv7, версии), inbox, курсоры, NOTIFY
0018_platform_edge.sql   край платформы: rate limit (GCRA), решения антибота, заголовки ответа идемпотентности
0019_geo.sql             geo: источник GeoNames, названия по локалям, история slug, точки и geoname_id городов, архив районов, geo_read_city_settings; app_versions (платформа)
0020_staff.sql           сотрудники (staff_*): учётки, роль и города модератора, TOTP, резервные коды, приглашения, сессии; approvals и staff_idempotency_keys — ключи идемпотентности admin-api, права только admin (платформа); audit_log: автор-сотрудник, снимок имени, город; role_assignments — только допуск капитана
0021_geo_admin.sql       geo 2/2 в админке: feature_flags.version, store_url без пробельных и управляющих, CHECK форматов правил страны; DELETE истории slug у admin — в grants.sql
0022_staff_rate_limits.sql  staff_rate_limits — лимиты admin-api (копия rate_limits, UNLOGGED), права только admin; у admin на rate_limits — ничего (grants.sql)
0023_normalize_text_case.sql  normalize_text без учёта регистра (все строчные латинские двойники, диакритика до них); пересчёт семи *_normalized и хранимых ников
```

Правка миграции: пока она не слита в `main` и не накатана на стенд (стенд накатывает `migrate up` из `main`,
`docs/deploy-dev.md`), её можно править на месте — так правилась `0020` в плане сотрудников A до мержа. После
мержа в `main` — только новой миграцией.

Goose помнит накатанную версию и правку на месте не накатит: базу пересоздают **все, кто накатывал прежнюю
редакцию** (локальная `wf` каждого разработчика; шаблоны тестовых баз pgtestdb пересоздаются сами — ключ
шаблона — хэш миграций). Обычно хватает `./task backend:db:reset`. Если откат падает — раздел Down новой
редакции не совпадает со схемой прежней (например, удаляет таблицу, которую прежняя не создавала), — базу
пересоздать целиком:

```bash
bash scripts/pg.sh psql -d postgres -c "DROP DATABASE wf WITH (FORCE)"
bash scripts/pg.sh psql -d postgres -c "CREATE DATABASE wf OWNER migrator"
./task backend:db:migrate
```

Расширения база наследует из `template1`, права ролей выдаёт сам `migrate up`.

Накат — через `cmd/migrate` (goose библиотекой, не CLI):

```
./task backend:db:migrate
```

## Что защищено на уровне базы, а не кода

Это главная ценность схемы: перечисленное ниже нельзя сломать багом в приложении
или гонкой двух одновременных запросов.

| Правило | Механизм |
| --- | --- |
| Два матча на одном поле в пересекающееся время | `EXCLUDE USING gist` + зазор 10 минут после свистка |
| Отменённый матч освобождает слот | предикат `WHERE status IN (...)` в том же констрейнте |
| Дворовая коробка не блокирует слот | флаг `blocks_pitch` в предикате |
| Одинаковые названия команд в одном городе | уникальный индекс по `(city_id, name_normalized)` |
| Клон названия латиницей («MOCKBA», «mockba») и регистром («Tom»/«tom», с `0023`) | `normalize_text()`: `lower()`, затем все строчные латинские двойники — в кириллицу |
| Один капитан — одна команда в городе | уникальный индекс по `(captain_id, city_id)` |
| Платный матч без суммы и бесплатный с суммой | два взаимных check-констрейнта |
| Прогнозы за купленную валюту | `CHECK (stake_kind = 'points')` — механика физически не может стать азартной |
| Голос за себя как за лучшего игрока | `CHECK (voter_id <> nominee_id)` |
| Публичная метка неплательщика от одного капитана | `CHECK (NOT is_public OR distinct_markers >= 2)` |
| Больше трёх снятых броней позиции | триггер `position_reservations_revoke_limit` |
| Возрастной порог команды ниже 14 | `CHECK (min_age >= 14)` |
| Изменение или удаление записи аудит-лога | триггер, который всегда бросает исключение |
| Две пересекающиеся подписки одного тира | `EXCLUDE` по `(user_id, tier, период)` |
| Один город заведён из места GeoNames дважды (в том числе гонка двух активаций) | `UNIQUE` `cities_geoname_id_key` |
| Два импорта одной страны одновременно | частичный уникальный индекс `geonames_imports_running` (`status = 'running'`) |
| Два активных района с одним именем в городе | частичный уникальный индекс `districts_city_name_active_key` (`archived_at IS NULL`) |
| Город без точки | `cities.centroid NOT NULL` (с `0019`) |
| Битый `slug` в ссылке на город | `CHECK` `cities_slug_format`, `city_slug_history_slug_format`: `[a-z0-9]`, дефис между частями, до 100 символов |
| Минимальная версия приложения не semver или стор не по `https` | `CHECK` на `app_versions` (`MAJOR.MINOR.PATCH` без ведущих нулей) |
| Пробельный или управляющий символ в `store_url`, схема не `https://` в нижнем регистре (с `0021`) | `CHECK` `app_versions_store_url_check` (`^https://[^[:space:][:cntrl:]]+$`); U+00A0 и U+0085 ловит код (`appversion.Validate`) |
| Правила страны не в формате: код не ISO alpha-2, валюта не три заглавные, язык не две строчные, префикс не `+` и 1–4 цифры (без ведущего нуля), возраст вне 1–120 (с `0021`) | `CHECK` `countries_code_format`, `countries_currency_format`, `countries_default_locale_format`, `countries_phone_prefix_format`, `countries_ages_range` (порядок порогов — `countries_age_order`); действующие ISO и поддерживаемые локали проверяет код |
| Версия флага функции не положительная (с `0021`) | `CHECK` `feature_flags_version_check` |
| Публичный API стирает счётчики перебора входа сотрудников или закрывает им вход большим `tat` (с `0022`) | своя таблица `staff_rate_limits`, права только у `admin` (ветка `staff_*` в `grants.sql`); у `admin` на `rate_limits` — ничего |
| Две учётки сотрудника на одну почту, почта не в нормализованном виде | `UNIQUE` `staff_accounts_email_key` (`citext`), `CHECK` `staff_accounts_email_format` |
| Модератор без городов или города у не-модератора | отложенный триггер `staff_role_cities_check()` (на `COMMIT`, `23514` `staff_role_cities_moderator`) |
| Два живых приглашения у одной учётки; код у закрытого приглашения | частичный уникальный индекс `staff_invites_live_key`; `CHECK` `staff_invites_closed_no_code`, `staff_invites_code_pair` |
| Живое приглашение без кода (стёртый код у незакрытого, в том числе истёкшего: стереть — только закрыв через `revoked_at`) | `CHECK` `staff_invites_live_has_code` |
| Активная сессия сотрудника без второго фактора | `CHECK` `staff_sessions_active_mfa` |
| Подтверждение своего запроса или запроса о себе; отмена чужого запроса | `CHECK` `approvals_two_hands`, `approvals_cancel_by_initiator` |
| Запись журнала с двумя авторами, без роли, служебная роль у автора, сотрудник без снимка имени | `CHECK` `audit_log_one_actor`, `audit_log_service_actor`, `audit_log_staff_actor` |

## Решения, которые стоит знать

**Деньги.** Платформа не принимает и не хранит оплату аренды. `matches.rent_total_minor`
и `match_participants.share_minor` — справочный расчёт, `payment_notes` — заметки капитана.
Все суммы в минорных единицах (`bigint`), валюта берётся из страны города и пишется
в каждую запись матча: если валюта страны когда-нибудь сменится, старые матчи не должны
пересчитаться задним числом.

**Возраст.** Хранится дата рождения, возраст считается функцией `age_years()` на нужную дату.
Никакого поля `is_minor`: оно должно переключаться само в день восемнадцатилетия.
Пороги живут в `countries.min_signup_age` и `countries.age_of_majority` — в сиде заполнена
только Россия (14 и 18), для остальных стран числа нужно уточнять у юриста.

**Роли.** Роли игроков — `role_assignments (user_id, role, scope_type, scope_id)`, а не колонка в `users`.
Без этого первая же ситуация «капитан в одной команде, игрок в другой» ломает модель. С `0020` в ней только
допуск к капитанству в городе (`captain`, `city`): роли сотрудников живут в `staff_roles`
(`docs/05-ролевая-модель.md`), капитан и вице команды — данные `teams`.

**Статистика.** Считается в снапшоты (`*_daily`, `reliability_snapshots`) ночным пересчётом.
Агрегат по всей истории на каждый открытый экран — первое, что ляжет при росте.
`player_stats_daily.diversity_weight` понижает вес статистики, если последние матчи
сыграны с одними и теми же людьми: это защита не от выдуманных голов, а от выдуманных матчей.

**Незакрытый протокол.** Через 72 часа матч уходит в `expired` и не учитывается нигде —
ни в статистике, ни в надёжности, ни в паспорте команды. Команда, которой статистика
не нужна, должна мочь пользоваться приложением только ради сбора людей.

**Устаревший комментарий в `0002_geo.sql`.** Там сказано, что капитанство привязано к
`age_of_majority`. Решение 01.10.2026: порог капитана — `min_signup_age` страны (для
России 14). Применённые миграции не правятся, источник истины — спека бэкенда §7.1.

**События (спека бэкенда §6.5).** `outbox.id` — UUIDv7 из Go, `occurred_at` — время транзакции.
Триггер `outbox_notify` (на оператор, канал `wf_outbox`) будит relay воркера; relay ставит задачу
River на каждого подписчика и отмечает `published_at` в одной транзакции. Подписчик пишет
`event_inbox (subscriber, event_id)` в своей транзакции — повтор доставки не задваивает;
подписчик состояния ведёт `event_cursors` и отбрасывает событие со строго меньшей версией.
Опубликованный outbox и inbox чистятся через 30 дней.

**Край платформы (спека бэкенда §6.4, §6.6, §6.7).** `rate_limits` и `humancheck_spent` — `UNLOGGED`:
без WAL, после сбоя сервера пусты (короткое окно без лимита и повтора PoW допустимо). Ключ лимита —
`<вид>:<класс>:<значение>`, собирается только `ratelimit.IPKey` / `SubjectKey` / `SessionDeviceKey` /
`BFFDeviceKey` / `EmailKey`: `ip:auth:203.0.113.7`; субъект — игрок `user:default:<uuid>` или сотрудник
`staff:default:<uuid>` (счётчики раздельны); почта (вход сотрудника) — `email:<класс>:<base64url(hmac)>`,
сама почта не хранится; у устройства значение с префиксом источника — `device:<класс>:s:<uuid>`
(устройство сессии) или `device:<класс>:b:<метка>` (метка BFF), чтобы метка из cookie не совпала с чужим
устройством. Строка одна на ключ, `tat` — GCRA,
интервал усечён до микросекунды (точность `timestamptz`). Ключи admin-api (`staff:`, `email:`, `ip:staff_auth`,
потолок аудита приглашений) с `0022` живут в своей таблице `staff_rate_limits` (копия `rate_limits`, тоже
`UNLOGGED`; права только у `admin`, чистит тикер admin-api): у роли `api` на `rate_limits` DML, и взлом
публичного API иначе давал бы рычаг над входом в админку (план B, R2). Решение PoW
хранится до `expires_at` задачи. `idempotency_keys` хранит ответ повтора: статус, тело (`jsonb`) и
заголовки `Content-Type`, `Location`, `ETag` (`response_headers`); ключ живёт 24 часа.

**Справочник geo (`0019`, спека `docs/superpowers/specs/2026-10-02-geo-design.md` §3).**
Идентичность города — `geoname_id` места GeoNames (без внешнего ключа: источник перезагружаем, город —
нет). Уникальность `(страна, нормализованное имя)` снята: в России 269 тёзок по GeoNames, 41 — внутри
одного региона, а `normalize_text` даёт `''` для письменностей кроме латиницы и кириллицы; по имени
остался неуникальный индекс для поиска. Названия — в `country_names`, `region_names`, `city_names` по
локалям; строка на языке страны — источник канонического `name`, импорт дописывает только
отсутствующие строки. Районы не удаляются, а архивируются (`archived_at`): на них ссылаются поля и
вызовы; имя архивного района свободно. Старые `slug` города живут в `city_slug_history`.
Экспортированное представление — `geo_read_city_settings` (прежнее `city_settings` удалено).
`app_versions` — таблица платформы (минимальная версия приложения). Права ролей на всё это —
ветки `grants.sql` (спека geo §3.8). Сид получил точки, `geoname_id`, население и названия ru/en;
если в базе есть другие города без точки, `0019` падает со списком их `slug` — заполнить
`centroid` и повторить `migrate up`. Комментарий раздела данных в `0019_geo.sql` («трогаются только строки
сида 0010») точен не целиком: точки, `geoname_id`, население, код admin1 и en-названия получают только строки
сида, а строки названий на языке страны (`country_names`, `region_names`, `city_names` из канонического `name`)
`0019` заводит всем странам, регионам и городам базы; новых городов она не заводит. Текст `0019` не правится:
она слита и накатана на стенд. Поиск места по ascii-названию идёт по генерируемой
`geonames_places.ascii_name_normalized`: индекс по выражению с `normalize_text` не строится (с PG17
`CREATE INDEX` вычисляет выражения с `search_path = pg_catalog, pg_temp`).

**Откат `0019`** возвращает схему `0002` в точности (тест `migrations/geo_0019_test.go`), но упадёт
на построении уникальных индексов, если после `0019` заведены тёзки в одной стране
(`cities_country_name_key`) или архивный район делит имя с активным (`districts_city_name_key`) —
это ожидаемо: данные важнее симметрии отката. Переводы, история `slug`, источник GeoNames и версии
приложения при откате теряются.

**Сотрудники (`0020`, спека `docs/superpowers/specs/2026-10-06-staff-admin-geo2-design.md` §3,
`docs/05-ролевая-модель.md`).** Отдельные учётки `staff_*`, с `users` не связаны; права БД — только у
`admin` (`api` и `worker` не видят ничего, задачи сотрудников исполняет admin-api). Секреты в базе только
зашифрованы или захэшированы, у каждой строки — `key_id` ключа (имя `keys.ID`): секрет TOTP и код
приглашения — AES-256-GCM (у кода aad = id приглашения), резервные коды — HMAC-SHA-256, токен сессии —
SHA-256. Код приглашения (`xxxxx-xxxxx`, 50 бит) стирается (`code_enc = NULL`) только при закрытии
приглашения (`CHECK` `staff_invites_closed_no_code`; живое без кода — `staff_invites_live_has_code`, код у
живого, в том числе истёкшего, стирают только вместе с `revoked_at`); неверные вводы его не стирают и в строке не считаются
(решение пользователя 14.10.2026: стирание давало анонимно срывать приглашение). Города модератора
проверяет отложенный триггер: роль и города меняются одной транзакцией в любом порядке. Триггер не
защищает от гонки: при READ COMMITTED две транзакции, снимающие разные последние города одного
модератора, проходят обе. Поэтому любая правка роли или городов в той же транзакции блокирует строку
учётки — `UPDATE staff_accounts SET version = version + 1` (спека §3.1); вторая транзакция ждёт первую.
id — UUIDv7 из Go, время — из `clock.Clock`, поэтому умолчаний у них нет.
Подтверждения вдвоём — таблица платформы `approvals` без внешних ключей; имена инициатора и решившего —
снимком. Решённое без решившего — только просрочка или отмена системой, с меткой `system`; отменить
сам может только инициатор, и без `error` (`initiator_changed` — у отмены системой). `audit_log` получил
автора-сотрудника, снимок имени и город записи; роль у записи обязательна, запись без автора — только
`system`, `operator` или `anonymous`. `role_assignments` пересоздал типы ролей (`ALTER TYPE … DROP VALUE` в PostgreSQL
нет); строки с ролями сотрудников `0020` отвергает с понятным текстом — перенести или удалить их и
повторить `migrate up`.

**Откат `0020`** возвращает схему `0019` в точности (тест `migrations/staff_0020_test.go`): учётки,
сессии и подтверждения сотрудников, авторы-сотрудники, снимки имён и города записей журнала при откате
теряются.

**geo 2/2 в админке (`0021`, спека сотрудников §3.2, §6.3 п.6; план B, R12).** `feature_flags.version` —
оптимистичная версия `PATCH /v1/flags/{key}` (сид получает 1). CHECK `store_url` и форматов страны — защита в
глубину: код проверяет строже (действующие ISO 3166-1 и ISO 4217, поддерживаемые локали, хост стора). Строка,
не проходящая новый CHECK, валит `0021` целиком (`23514` с именем ограничения, версия остаётся 20): исправить
данные и повторить `migrate up`; данные стенда сверяются до мержа (план B, Task 25). Откат возвращает схему
`0020` в точности (тест `migrations/geo_0021_test.go`), версии флагов теряются.

**`normalize_text` без учёта регистра (`0023`, решение пользователя 28.10.2026).** В `0001` строчные латинские
`b h m t` оставались латиницей, а заглавные уходили в кириллицу: `mikh` не находил Mikhaylovsk, «Tom» и «tom» были
разными никами; буква с диакритикой оставалась латиницей («Café» ≠ «Cafe»). Новая функция: `unaccent` → `lower` →
12 строчных латинских двойников (`abcehkmoptxy`) в кириллицу → только `[a-zа-яё0-9]`; `immutable_unaccent` — со
схемой. Новое значение = `translate(старое, 'abcehkmoptxy', 'авсенкмортху')` для любого текста: так пересчитаны
хранимые ники без исходника (`reserved_nicknames`, карантин `nickname_reservations`; совпавшие схлопнуты, у
карантина — поздний срок) и так считается проверка стенда до мержа (`docs/deploy-dev.md`). Семь генерируемых
`*_normalized` пересчитаны `ALTER COLUMN … SET EXPRESSION` (переписывание таблицы и её индексов, без триггеров).
Совпадение строк уникального индекса после пересчёта валит `0023` целиком (`23505` с именем индекса, версия
остаётся 22). Откат возвращает функцию `0001` дословно и прежние значения колонок (конфликтов не бывает: прежняя
функция различает не меньше), хранимые ники остаются в новой форме, ники сида `0010` возвращаются в прежней (тест
`migrations/platform_0023_test.go`).

**Запланированные изменения.** Спека бэкенда (`docs/superpowers/specs/2026-10-01-backend-architecture-design.md`,
§11) перечисляет миграции, которые добавят план «фундамента» и спеки модулей: таблицы входа и устройств, `player_profiles`,
`version` у матчей и протоколов, новые покрытия полей. Таблица выше обновляется по мере
их появления.

## Что осталось за пределами схемы

Турнирные сетки (`competitions` есть, генерация пар — нет), расчёт Elo, конкретные формулы
надёжности и diversity_weight, тексты уведомлений. Это логика приложения, а не структура данных.
