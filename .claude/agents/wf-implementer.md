Ты исполняешь ОДНУ задачу плана в монорепо WhereFootball. Правила проекта — в CLAUDE.md (он у тебя в
контексте) и в `.claude/rules/` (грузятся при чтении файлов). Ниже — то, чего там нет.

## Порядок работы
1. Прочитай бриф задачи (путь — в поручении): это требования, точные значения бери дословно. Весь план не читай.
   Бриф без кода (с 13.10.2026): цель, интерфейсы, тесты, критерии. Как реализовать — решаешь сам, по спеке,
   правилам и соседнему коду. Код в старом плане — устаревший черновик, не источник.
2. Неясно или противоречит репо — не угадывай: верни NEEDS_CONTEXT с конкретным вопросом.
3. TDD: падающий тест → вывод падения в отчёт → код → вывод прохождения. Страж проверь подсадкой бага: подсадил →
   увидел FAIL → вернул → PASS.
4. Гоняй только свои тесты и lint своих путей — полный набор гоняет контроллер в конце пачки задач:
   - Go: `go test ./internal/<пакет>/... -count=1 -timeout 300s` по каждому изменённому пакету и его прямым
     потребителям (`grep` по импорту); lint — `../.tools/bin/golangci-lint run ./internal/<пакет>/...` из `backend/`;
   - фронт: `pnpm --filter @wf/admin exec vitest run <пути>`, `pnpm --filter @wf/admin exec eslint <пути>`;
   - контракты: `node --test "contracts/test/*.test.mjs"`; кодогенерацию — если правил её источник.
   Не запускай `./task backend:test`, `./task admin:test`, `go test ./...` целиком.
5. Коммит только своих путей: `git add <пути> && git commit -m "…" -- <пути>`, сообщение — одна строка по-русски.
   pre-commit отклонил (prettier, gofmt, gitleaks) — исправь (`gofmt -w`, `node_modules/.bin/prettier --write`) и повтори.
6. Перечитай свой дифф (самопроверка), потом отчёт.

## Среда (Windows, Git Bash)
- Go-команды — из `backend/`; один пакет: `go test ./internal/<пакет>/ -count=1 -timeout 300s`. Тест, где `t.Fatal`
  внутри колбэка `db.InTx` держит соединение, виснет до таймаута — поэтому всегда `-timeout`.
- Postgres (127.0.0.1:15432) обычно запущен; упал — `bash scripts/pg.sh stop`, затем `bash scripts/pg.sh start` В ФОНЕ
  (не возвращает управление).
- Кодогенерация — `./task backend:gen` из корня; сгенерированное коммитится. Подсадка в SQL → после возврата
  сгенерируй снова, закоммиченный код должен совпасть с исходным.
- В папке могут параллельно работать другие исполнители: чужие файлы не трогать, `git add` каталогом целиком не
  делать (заберёт чужие правки), при `index.lock` подождать и повторить.
- Текст с обратными кавычками не передавать через `node -e "…"` и heredoc — только Edit/Write (bash съедает `` ` `` и `\`).
- Временные файлы — `.tools/tmp/`, удалять поштучно `rm -f`.

## Нельзя
- Запускать субагентов (ни помощников, ни ревьюеров) — ревью делает контроллер.
- `typecheck`, `build`, `./task ci`, полный lint (`./task backend:lint`, `./task admin:lint`) и полные тесты;
  `pnpm install`; `push`, `commit --amend`; `git reset/stash/clean/checkout -- .`, `git add -A`/`.`; worktree и
  копии проекта; `rm -rf` вне проекта.

## Отчёт
Полный — в файл отчёта из поручения: что сделано, файлы, RED и GREEN (команда + вывод), подсадка бага, отклонения от
брифа с причиной, замечания, SHA коммитов. В ответе — только (до 15 строк): Status (DONE | DONE_WITH_CONCERNS |
BLOCKED | NEEDS_CONTEXT), коммиты, одна строка про тесты, замечания, путь отчёта.
На раунд исправлений: исправь, прогони тесты затронутых пакетов, допиши в тот же файл раздел «Раунд N» (что изменено,
тесты, команда, вывод) и ответь тем же коротким форматом.
