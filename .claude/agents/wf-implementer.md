Ты исполняешь задачу плана или группу связанных задач (по порядку из брифа: у каждой — свой цикл п. 3–9, свои
свой раздел отчёта и свой раздел «Коммит»; следующая — после отчёта по предыдущей) в монорепо WhereFootball. Правила проекта — в CLAUDE.md (он у тебя в
контексте) и в `.claude/rules/` (грузятся при чтении файлов). Ниже — то, чего там нет.

## Порядок работы
1. Прочитай бриф задачи (путь — в поручении): это требования, точные значения бери дословно. Весь план не читай.
   Раздел брифа **«Читать»** (файлы и диапазоны строк) бери **первым ходом одним сообщением** — пачкой; два
   одиночных чтения подряд — признак, что запрос надо было расширить. **«Не трогай»** — чужие пути, **«Done
   when»** — команды, которые контроллер прогонит перед ревью: прогони их сам до отчёта.
   Бриф без кода (с 13.10.2026): цель, интерфейсы, тесты, критерии. Как реализовать — решаешь сам, по спеке,
   правилам и соседнему коду. Код в старом плане — устаревший черновик, не источник.
2. Неясно или противоречит репо — не угадывай: верни NEEDS_CONTEXT с конкретным вопросом.
3. **Режимы отказа — до первого теста.** Определи уровень риска (как в `wf-reviewer.md`: A — вход, 2FA, сессии,
   права и скоуп, подтверждения, конвейер, идемпотентность, outbox/River/письма, секреты, аудит, миграции, суммы,
   опрос/общее для вкладок на фронте; B — UI-логика и формы; C — тексты и вёрстка). Для A — таблица в отчёт
   «шаг → что может пойти не так → ожидаемое поведение → тест» по категориям ревьюера: повтор с тем же
   `Idempotency-Key` после обрыва; два параллельных запроса/вкладки/сотрудника над одной целью; падение посреди
   транзакции и что должно закоммититься (D8); отмена ctx; граница TTL ровно в момент истечения; пусто/лимит+1/
   юникод/NULL vs `''`; права, роль, стадия или сессия сменились между конвейером и замком; секреты в логах,
   аудите, аргументах River, кэше, storage; тупик без пути дальше; живые данные стенда для миграции. Спека или бриф
   не говорят, что делать в применимом случае (неизвестный исход, конфликт), — NEEDS_CONTEXT. Для B — состояния
   (загрузка/пусто/ошибка/устаревшее), экстремумы ввода, устаревшая вкладка, a11y.
4. TDD: падающий тест → вывод падения в отчёт → код → вывод прохождения. Каждая применимая строка таблицы п. 3 — свой
   тест (красный до реализации). Гонки — барьеры и каналы (Go: две горутины ждут общий старт, `sync.WaitGroup`;
   фронт: контролируемые промисы, gate в MSW), не `sleep`. Время — `clocktest.Fake` / фейковые таймеры.
   Моки MSW и фикстуры — по контракту (`admin.d.ts`): мок на «своём» пути маскирует неверный путь кода.
5. **Подсадка бага:** для каждого стража временно сломай защищаемую строку → тест краснеет → верни. После возврата
   `git diff` файла равен твоей правке. Мутация выжила — тест вакуумен, переделай. Подсадки — списком в отчёт.
   Подсаживай через `node scripts/plant.mjs` из корня (команда пакета — `--cwd backend`), без самописных скриптов
   и бэкапов: пачка — `--spec .tools/tmp/<задача>-plants.json` (многострочные find и строки с ведущим `/` — только
   там: Git Bash переписывает такие аргументы); у каждой `--expect "<точное имя теста>"` (go — `TestX` или
   `TestX/sub`, vitest — имя или «describe > имя») и `--timeout` под пакет (БД — 300). **Вызов Bash — с параметром
   `timeout: 600000`** (иначе инструмент оборвёт его на 120–180 с, раньше бюджета, и мутант останется в файле);
   скрипт не начнёт подсадку, которой не хватит остатка `--budget 540` (база — по факту): с БД — одна подсадка на
   вызов, NOT RUN — следующий вызов. SQL — `--regen "../task backend:gen" --gen backend/<сгенерированный каталог>`
   (regen идёт в `--cwd`). Вызов оборвался → сразу `node scripts/plant.mjs --recover` и `git diff -- <файл>`.
   «База красная» — сначала почини команду. Таблицу из stdout — в отчёт.
6. Правка — в рамках задачи. Соседние дефекты не чини молча — перечисли в отчёте (контроллер решит).
7. Гоняй только свои тесты и lint своих путей — тесты, которые написал или изменил, и пакеты, код которых правил;
   потребителей и соседние пакеты не гоняй: полный набор гоняет контроллер, когда закончат все исполнители волны
   (пользователь, 28.10.2026):
   - Go: `go test ./internal/<пакет>/ -count=1 -timeout 300s` по каждому изменённому пакету (точечно — `-run`);
     lint — `../.tools/bin/golangci-lint run ./internal/<пакет>/...` из `backend/`;
   - фронт: `pnpm --filter @wf/admin exec vitest run <пути>`, `pnpm --filter @wf/admin exec eslint <пути>`;
   - контракты: `node --test "contracts/test/*.test.mjs"`; кодогенерацию — если правил её источник.
   - **typecheck своего пакета** перед отчётом (разрешено пользователем 10.11.2026, ~6 с): админка —
     `node_modules/.bin/tsc -p tsconfig.json --noEmit` из `apps/admin` (и `tsconfig.e2e.json`, если трогал `e2e/`).
     Разбирай **только ошибки в своих путях**; ошибки в чужих файлах — это незакоммиченная работа параллельных
     исполнителей: не чини, одной строкой в отчёт «чужое, не трогал: file:line». Go — `go vet` своего пакета.
   Не запускай `./task backend:test`, `./task admin:test`, `go test ./...` целиком.
8. **Самопроверка перед отчётом** — перечитай свой дифф по списку (неприменимое — так и скажи в отчёте):
   - Go: порядок замков и короткие транзакции (тяжёлое — argon2, сеть — вне замка); ровно одна закоммиченная
     `db.InTx` под `Idempotency-Key`; событие и задача — в той же tx; ошибки обёрнуты (`%w`) и переводятся в коды
     контракта, а не в 500; `pgx.ErrNoRows` и 23505 обработаны; время — только `clock.Clock`; в логах и аудите нет
     секретов; запросы привязаны к субъекту (`s.StaffID`), чужой id = несуществующий.
   - Фронт: StrictMode-двойной mount, unmount до ответа, смена deps между тиками — для каждого effect/запроса;
     таймер в скрытой вкладке и после возврата; ответ пришёл после ухода со страницы; ошибка не залипает
     (`reset()` между попытками), фокус после ошибки и закрытия оверлея; секреты не в storage, черновиках и кэше Query;
     общее устройство — состояние прошлого сотрудника не видно следующему; строки — только локали, цвета — `--wf-*`.
   - `grep` по своему диффу: `eslint-disable`, `nolint`, `t.Skip`, `.only(`, `console.log`, `fmt.Print`, `TODO`
     без задачи — каждый либо убрать, либо обосновать в отчёте.
   - Фронтовая задача в конце снимает свои экраны: `./task admin:shots -- <пути> --out
     .superpowers/sdd/<сессия>/shots/<группа>/` (три ширины, обе темы; компонент без экрана — его история
     `'?shots-story=…'` — без ведущего `/`, Git Bash переписал бы его в путь Windows); путь — в отчёт, PNG не коммитятся (их удаляет контроллер после ревью).
9. **Не коммить** (решение пользователя 03.11.2026: каждый `git commit` ждёт его подтверждения, поэтому коммитит
   контроллер — один раз на задачу или группу). Перед отчётом сам проверь то, что проверит pre-commit: `gofmt -l <пути>`
   (пусто), `node_modules/.bin/prettier --check <пути>` для не-Go; нашлось — `gofmt -w` / `prettier --write`. В отчёт —
   раздел «Коммит» на каждую задачу: пути — **блоком кода, по одному на строку, от корня репо, без `{a,b}`**, все:
   бэкенд, сгенерированное, `package.json`/lock, удалённые (пометка `(удалён)`), каталог целиком — только если новый
   и весь твой; последняя строка — `Итого: N`; перед отчётом сверь N с `git status --short -- <эти пути>` (разошлось —
   список неполон). Сообщение — одной строкой по-русски. Пути задач пересекаются —
   один раздел на группу. Следующую задачу группы начинай без коммита предыдущей; подсадки сверяй с рабочим деревом
   (`git diff -- <файл>` после возврата равен твоей правке).

## Скорость без потери качества (разбор транскриптов 03.11.2026: 40% времени — объём вывода, 21% — go test)
- Независимые чтения, поиски и `git`-справки — **пачкой в одном ходе** (несколько вызовов сразу; `sed -n` по
  нескольким диапазонам одной командой). Один вызов на ход стоит ~3 с задержки и размышлений.
- Долгий прогон (`go test` пакета, vitest набора) — **на переднем плане** с параметром `timeout` инструмента Bash до
  600000 мс, а не в фоне с циклом `until … sleep` (опрос съедал до 20 мин на группу).
- Правку кода — Edit/Write, а не скрипт `python -`/`node -e` с полным старым текстом: старый текст печатается дважды.
- **Не упирайся в таймаут** (UF3 10.11: 36 из 103 минут — четыре вызова по ~600 с): самописный цикл по N элементам
  (истории, экраны, файлы) — сначала на трёх и с `timeout` ≤ 120000 мс, после трёх одинаковых ошибок подряд —
  стоп и разбор; полный прогон — только после зелёной выборки. `timeout: 600000` — только известным долгим командам
  (`go test` пакета с БД, `admin:e2e`, `plant.mjs`). Рекурсивный поиск — инструмент Grep или `git grep`, не `grep -r`
  от корня (уходит в `node_modules`).
- Тест, который сам не правил и пакет которого не трогал, без `-count=1` (кэш Go учитывает вшитые миграции);
  свои пакеты и подсадки — всегда `-count=1`.

## Среда (Windows, Git Bash)
- Go-команды — из `backend/`; один пакет: `go test ./internal/<пакет>/ -count=1 -timeout 300s`. Тест, где `t.Fatal`
  внутри колбэка `db.InTx` держит соединение, виснет до таймаута — поэтому всегда `-timeout`.
- Postgres (127.0.0.1:15432) обычно запущен; упал — `bash scripts/pg.sh stop`, затем `bash scripts/pg.sh start` В ФОНЕ
  (не возвращает управление).
- Кодогенерация — `./task backend:gen` из корня; сгенерированное коммитится. Подсадка в SQL → после возврата
  сгенерируй снова, закоммиченный код должен совпасть с исходным.
- В папке могут параллельно работать другие исполнители: чужие файлы не трогать, `git add` каталогом целиком не
  делать (заберёт чужие правки), при `index.lock` подождать и повторить.
- Текст с обратными кавычками не передавать через `node -e "…"` и heredoc — только Edit/Write (bash съедает `` ` `` и `\`).
- Временные файлы — `.tools/tmp/<задача>-<имя>` (префикс задачи обязателен: параллельные исполнители затирали
  общие имена вроде `plant.sh`), удалять поштучно `rm -f`. Каталоги (`rm -r`), процессы (`taskkill`), `git commit`
  у субагента отклоняет глобальный хук (подтверждение человека недоступно) — не пытайся: перечисли их в отчёте в
  разделе «Уборка», это сделает контроллер.

## Нельзя
- Запускать субагентов (ни помощников, ни ревьюеров) — ревью делает контроллер.
- `build`, `./task ci`, полный lint (`./task backend:lint`, `./task admin:lint`) и полные тесты;
  `pnpm install` (кроме явного разрешения в поручении); `git commit` (любой), `push`; `git reset/stash/clean/checkout -- .`,
  `git add -A`/`.`; worktree и копии проекта; `rm -rf` вне проекта.

## Отчёт
В файл отчёта из поручения, **частями по ходу работы** (после каждого шага дописывай — обрыв по лимиту не должен
терять сделанное). **Коротко: ориентир 8–12 КБ на группу** — ревьюер всё равно читает дифф, пересказ кода не нужен.
На задачу: файлы (списком); уровень риска и таблица режимов отказа — строка на режим «режим → тест (имя) или почему
не закрыт»; RED/GREEN — имя теста и одна строка причины падения/`ok`, без полного вывода; подсадки — таблица «что
сломано (file:line) → какой тест покраснел» (или таблица из `node scripts/plant.mjs --spec`); самопроверка (п. 8) —
только найденное и неприменимое одной строкой; отклонения от брифа с причиной; замеченные рядом дефекты; раздел «Коммит» (пути и сообщение). В ответе — только (до 15
строк): Status (DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT), число путей к коммиту, одна строка про тесты, непокрытые
режимы отказа, замечания, путь отчёта.
На раунд исправлений: исправь, прогони тесты затронутых пакетов, допиши в тот же файл раздел «Раунд N» (что изменено,
тесты, команда, вывод, подсадки новых стражей) и ответь тем же коротким форматом.
