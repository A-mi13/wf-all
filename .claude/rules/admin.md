# Админка (`apps/admin`)

Спека — `docs/superpowers/specs/2026-10-06-staff-admin-geo2-design.md` §9. Общие правила фронтов — `frontend.md`.

- **Структура:** `src/app/` — роутер, провайдеры, сессия, права, guard'ы; `src/ui/` — набор компонентов; `src/features/<раздел>/` — экраны; `src/api/` — клиент и мутации; `src/i18n/` — язык.
- **Компоненты** — только из `src/ui` (импорт `../../ui`); своих кнопок, полей, модалок, таблиц и состояний в `features` не заводить. **Принципы (пользователь, 28.10):** (1) у каждого вложенного экрана — возврат к родителю общим `BackLink` (его рисует `AppShell` для любого адреса внутри раздела меню, на последний адрес родителя с его фильтрами), своих кнопок «назад» нет; (2) контролы форм и кнопки — только компоненты `src/ui`, нативные `<button>`/`<input>`/`<select>`/`<textarea>` в `features` и `app` запрещены (страж `src/ui/controls.test.ts`); (3) действие панели/диалога — в закреплённом подвале (`footer` у `Modal`/`Drawer`/`Sheet`; кнопка отправки формы из подвала — `type="submit" form={id}`), прокручивается только содержимое; (4) вёрстка без «прыжков» и случайных полос: горизонтальная прокрутка — с явным `overflow-y`, выбранное состояние не меняет метрик шрифта (страж `src/ui/layout-css.test.ts`). `src/app/stubs.tsx` — только «не найдено» и загрузка сессии (заглушек разделов больше нет).
  - Каркас — `AppShell` (`src/ui/shell`), его ставит роутер для стадии `active` (`ActiveShell` в `router.tsx`): меню из `NAV` (`src/app/nav.ts`), карточка «имя, почта (одна строка, многоточие, полная — `title`; без имени почта на его месте), роль · города» (`useAccountCard`, названия городов — `GET /v1/geo/cities?ids=`), под ней строками — переключатель языка «RU · EN» (`Segmented`), тема (`ThemeSwitch`) и кнопка «Выйти» во всю ширину (secondary с иконкой; `useLogout()` из `src/app/logout.ts`: `POST /v1/staff/auth/logout`, затем `session.afterLogout()` — вход без `return`: следующий сотрудник не попадёт в чужой раздел; стираются черновики форм (`clearDrafts()`) и кэш мутаций; `401` на выходе — так же; истёкшая сессия — по-прежнему с возвратом). Флаг «без return» живёт только во вкладке, где нажали «Выйти»: другие вкладки после 401 уходят на вход с `return` — осознанно, общий выход по вкладкам (BroadcastChannel) — по необходимости. Ширина < `breakpoint-mobile` — нижний таббар (до 4 разделов, открытых на телефоне) и «Ещё» (шторка: карточка, все разрешённые разделы, язык, тема, «Выйти»). Счётчик пункта — проп `counts` по `path` (число) и `NavItem.countLabelKey` (подпись для читалки, `{count}`); счётчик «Подтверждения» — `useIncomingApprovalsCount()` в `ActiveShell` (ниже, «Подтверждения»).
  - **Новый раздел:** путь — `paths.ts`; маршрут — ребёнок `shellRoute` в `router.tsx`; пункт в `NAV` — `{ path, labelKey, permission, icon, desktopOnly? }`. `permission` — ключ каталога (`null` — своё, любому активному). Пункта без права в меню нет, прямой адрес (и вложенные `/раздел/…`) — `ForbiddenState` сам AppShell; `desktopOnly: true` — на телефоне `DesktopOnlyState` (в таббар не попадает, в «Ещё» есть). Экран раздела проверку права не дублирует; страница начинается с `PageHeader` (единственный `h1`), вкладки — `Tabs` (управляемые, значение — search-параметр; счётчик — `count`, имя вкладки «Входящие 3»).
  - Списки — `DataTable` (`columns`, `rowKey`, данные — `{...infiniteTableProps(useInfiniteQuery(…))}` со страницами `{items, next_cursor}` и `getNextPageParam: (p) => p.next_cursor ?? undefined`): поиск (`search`, запрос уходит после паузы `SEARCH_DEBOUNCE_MS`; запоздавшее эхо отправленного значения набор не затирает), чипы (`chips`), раскрывающийся фильтр (`filters: { content, active }` — поля экрана; число заданных — в имени кнопки), сортировка (`sort` + `onSortChange`), «Показать ещё», карточки вместо строк (`card={(row) => <Card …/>}` — сетка, список с именем `label`, `columns={[]}`; «Города и запуск»), список выбора (`select: { value, onChange, onActivate, option }` — `role="listbox"` с `aria-activedescendant`, клик и ↑/↓/Home/End выбирают, Enter и двойной клик — `onActivate`; таблица заполняет высоту родителя, прокручивается только список; поиск места), «Показано N» (`summary={false}` — статичная таблица, например матрица прав), «Сбросить фильтры» (`dirty` + `onReset`); сам показывает скелетон, пусто (`empty` — своё пустое без фильтров, «Очередь пуста»), ошибку с кодом и «Повторить» (`retrying` — занята, пока идёт перезапрос). Роли строк и ячеек — явные: на телефоне строки-карточки, подпись столбца в ячейке видна и слышна. Фильтры и сортировку держит экран (search-параметры маршрута).
  - Состояния: `EmptyState`, `ErrorState` (код для поддержки + «Повторить»), `LoadingRows` (скелетон), `OfflineBanner` (`useOnline`; стоит в AppShell), `ForbiddenState`, `DesktopOnlyState`, `RateLimitedState` (`retryAfter` из `ApiError`, отсчёт; повторный 429 с тем же значением — `key={error}`; `page` — вместо страницы, заголовок `h1`), `PendingApprovalNotice` (после `202`), `ConnectionErrorState` (стадия `error` сессии: сеть и 5xx — «нет связи»; с `error` 4xx — «сервер не пустил», текст по коду и код для поддержки). Стадия `error` в `AppRouter`: me ответил 429 (лимит `staff_auth` по общему NAT) — `RateLimitedState page` с отсчётом, `403 auth.ip_not_allowed` и прочие 4xx — `ConnectionErrorState error` (ревью ветки M1).
  - Примитивы: `Button` (`variant`: primary | secondary | danger | danger-outline | link; `size="lg"` — вход; `loading` — `aria-disabled` + `aria-busy`, не `disabled`: фокус не падает на body, клик и неявная отправка формы гасятся; по умолчанию `type="button"`), `StatusChip` (`tone`, текст обязателен), `CountBadge` (0 не рисуется, >99 — «99+»), `Avatar` (инициалы, декоративный), `QrCode` (`value`, `label`; матрица — `uqr`, SVG-путь без inline-стилей, без сети), `Segmented` (сегменты в одну строку: `label` группы, `options` `{value, text, name?, title?, lang?}` — `name` начинается с видимого `text`, WCAG 2.5.3; сегмент-значок — `{value, icon, name, title?}`: видимого текста нет, `name` обязателен, `title` — для мыши; `aria-pressed`, `busy` — `aria-disabled`, фокус остаётся, нажатие гасится), `Switch` (`checked`, `onChange`, `label`, `hideLabel` — подпись только для читалки, `disabled`, `busy` — запрос в полёте: `aria-busy` + `aria-disabled`, фокус остаётся, нажатие гасится; `role="switch"` + `aria-checked`, Space/Enter — нативная кнопка), `Icon` (`name` из `@wf/icons`, `size` 16 | 20 | 24; без `label` — `aria-hidden`, с `label` — `role="img"`; толщина — `stroke-width` атрибутом: слой × `OPTICAL[size]`, у иконок меню `nav` — абсолютная; цвет — классами ролей: предмет — `currentColor`, деталь — `text-subtle`, акцент — `accent-ink`, тень акцента — `accent-detail` (токен-пара, темнее акцента в обеих темах), вырез — `bg-elevated` (на иной поверхности — класс родителя), вырез на акценте — `text-inverse`), `Illustration` (`size` 48 | 64, всегда декоративная, предмет — `text-muted`), `Card` (карточка «Города и запуск»: `title`, `chip`, `stats` `{value, label}[]`, `note`, `action` `{label, onClick}` — кнопка описана заголовком карточки, `selected` — только вид, `headingLevel`; `article` с именем по заголовку), `useCountdown()` (`{ left, start(seconds) }` — отсчёт 429 по `retryAfter` и паузы повторной отправки; `start` с тем же числом перезапускает).
  - **Тема** (спека UI-фундамента §4.12; `src/ui/theme`): выбор — `localStorage['wf.theme']` (`system` | `light` | `dark`; свойство браузера, не сотрудника — выход и смена сотрудника его не стирают), применение — атрибут `<html data-theme>`. До первого кадра его ставит `public/theme-init.js` (обычный скрипт-файл в `<head>` до стилей — CSP `script-src 'self'`; синтаксис ES5, Vite копирует как есть; storage бросает — `system`; без JS — статический `data-theme="system"` в `index.html`; admin-api отдаёт его с `no-cache`). `ThemeProvider` (внешний в `AppProviders`) при монтировании берёт атрибут (не storage), `useTheme() → { theme, resolved, setTheme }` (`resolved` — по `matchMedia('(prefers-color-scheme: dark)')` с подпиской, без `matchMedia` — `dark`; `setTheme` пишет storage в `try/catch` и `dataset` — не `element.style`), событие `storage` другой вкладки применяется; обе `<meta name="theme-color">` при явном выборе — `bg` темы, при `system` — `bg` темы своего `media` (из `tokens.ts`, совпадает с `index.html`). Разбор значения у скрипта и провайдера один (`parseTheme`, страж `theme-init.test.ts`). Цвет темы в JS — `useThemeColors()` (из `tokens.ts`, не `getComputedStyle`). `ThemeSwitch` — `Segmented` «Тема» из значков `monitor`/`sun`/`moon` («Система · Светлая · Тёмная»): карточка сотрудника, шторка «Ещё», экраны входа (`AuthLayout`, справа от бренда после языка). Смена — мгновенно, без анимации. Событие `storage` другой вкладки применяет текущее значение storage, а не `e.newValue` (две вкладки почти одновременно); явный выбор красит обе `theme-color` уже в `theme-init.js` (`BG` = `tokens.color.bg`, страж).
  - **Язык до входа** (решение пользователя 10.11; спека сотрудников §9.1 «Локали»): `useLocale()` (`src/i18n/locale.tsx`) — на `setup` и `active` `me.locale` (меняет `LocaleSwitcher` каркаса через `PATCH /v1/staff/me/locale`), на остальных стадиях (`anonymous`, `mfa_pending`, загрузка, ошибка) — выбор устройства `localStorage['wf.locale']` (`src/i18n/deviceLocale.ts`: чтение и запись в `try/catch`, неудачная запись держит выбор в памяти вкладки; пусто или мусор — язык браузера: `navigator.language` на `en` → `en`, иначе `ru`; событие `storage` другой вкладки применяется). `wf.locale` при выходе и смене сотрудника не стирается и после входа учётку не переписывает; на сервер уходит только язык экрана приглашения: `/accept` всегда шлёт `locale` = `useLocale()` (язык, на котором показан экран, — выбор устройства или язык браузера; не storage напрямую) в `staffAcceptInvite` — «что видишь, то и сохраняется»; сервер пишет его в учётку вместе с паролем — `me.locale` стадии `setup` совпадает, `/setup-2fa` без мигания на том же языке. Сброс доступа сотруднику с `en` на устройстве `ru-RU` перепишет язык на то, что выбрано на экране в момент принятия (переключатель рядом; принято осознанно, раунд 2 IL). `<html lang>` — за языком (`LocaleProvider`). Переключатель — `DeviceLocaleSwitcher` (`features/me/LocaleSwitcher.tsx`, тот же «RU · EN», что в карточке) в `AuthLayout` перед `ThemeSwitch`; на `setup` (`/setup-2fa`) не рисуется — там язык из `me.locale`, а `PATCH` до `active` сервер не примет. Строка «бренд · язык · тема» переносится по содержимому (`flex-wrap`, без `@media`): на 390 px в EN переключатели — своей строкой. В тестах язык браузера — `ru-RU` (`src/test/setup.ts`, геттер: тест языка подменяет его `vi.spyOn(navigator, 'language', 'get')`), в режиме shots у `anonymous` язык задаёт `--locale` скрипта (язык браузера).
  - Формы — `Form form={useForm()} onSubmit={(v) => m.mutateAsync(v)}` и поля `TextField` (`type`, в том числе `date` — значение `YYYY-MM-DD`), `PasswordField`, `SelectField`, `MultiSelectField` (`searchable`, `onSearch` — поиск на сервере), `CheckboxField`, своё поле через `Controller` + `FieldError`. Ошибка `onSubmit`: `validation.failed` → `body.<поле>` раскладывается по полям (текст `ui.field_errors.<код>`), остальное — `FormError` (`errors.<код>`, откат на `errors.internal`). Особые случаи (`attempts_left`, 429) — `onError` экрана, вернуть `true`. Текст ошибки по коду вне формы — только `useErrorText()` или `<FormError error={…} />`, своих откатов не писать.
  - `OtpInput` — код второго фактора: `onComplete(code)` один раз на полный ввод, после ошибки — `ref.current.reset()` (очистка, `onChange('')` — экран не отправит стёртый код — и фокус; пока ячейки `disabled` — фокус встанет, когда их включат); на время запроса — `busy` (ячейки `readOnly`, ввод и вставка гасятся, группа `aria-busy`; не `disabled` — фокус не падает на body), `disabled` — только когда ввод закрыт совсем (вход закрыт на час); резервный код — обычный `TextField`.
  - Оверлеи `Modal`, `Drawer` (панель справа), `Sheet` (шторка снизу), `ConfirmDialog` (`confirmWord` — слово или почта, точное совпадение с учётом регистра, пробелы по краям не считаются; пока `loading` — поле `readOnly`, кнопка `aria-disabled`; `children` — поля над вводом слова, например причина, в `FormProvider` экрана — у диалога своя `<form>`; `error` — ошибка запроса внутри диалога, он не закрывается и введённое не теряет): `open` + `onClose` у экрана, фокус-ловушка, Esc (только верхний), возврат фокуса на открыватель (запоминается до `autoFocus` содержимого), блок прокрутки — внутри. `dismissible={false}` / `loading` — пока идёт запрос. `ConfirmDialog` на узком экране сам становится шторкой (`useIsMobile`, порог — токен `breakpoint-mobile`).
  - Тосты — `useToast().success|info|error(текст, { action })`: успех и справка исчезают через 8 с (`TOAST_HIDE_MS`, пауза при наведении и фокусе), ошибка — только руками. Живые области постоянные и без ролей (`aria-live` polite/assertive): `getByRole('alert')` в тестах экранов находит только их ошибки. Порядок: успехи и справки — над ошибками, внутри области — по появлению. При открытой модалке тосты входят в цикл Tab; закрыли тост с фокусом (кнопкой или `dismiss(id)`) — фокус туда, откуда пришли, иначе на верхний диалог по стеку оверлеев. `ToastProvider` стоит в `AppProviders`.
  - `Form` гасит повторную отправку, пока идёт первая; ошибка не от API — `errors.internal` на экране и `console.error`.
  - CSP admin-api (`style-src 'self'`): во всём `src` (кроме тестов) нет атрибута `style`, `<style>`, `dangerouslySetInnerHTML` и записи в `element.style` — только CSS Modules; цвета — только `var(--wf-color-*)`. Страж — `src/ui/csp.test.ts`.
- **Экраны входа** (`src/features/auth`, Task 13; вне каркаса, `AuthLayout`): стадия сессии → маршрут (`guard.ts`): без сессии — `/login` (и `/accept`), `mfa_pending` — `/login` шаг 2 (и после перезагрузки), `setup` — только `/setup-2fa`, `active` — `?return=` или стартовая. Экран сам не навигирует: успех мутации → `session.refresh()`, остальное делает роутер.
  - `/login`: шаг 1 — `staffLogin` (анонимная: `security: []`, без `Idempotency-Key`), `staff.invalid_credentials` — общий текст, 429 — отсчёт, отправка недоступна; шаг 2 — `FactorForm` (`staffVerifyMfa`), `401 auth.unauthenticated` (5 минут вышли) — шаг 1 с пояснением. «Другая почта или пароль» и «Ко входу» запоминают брошенную сессию (`sessionId` стадии `mfa_pending`): её шаг 2 больше не показывается, неудачный вход остаётся на шаге 1 с ошибкой.
  - `FactorForm` — второй фактор входа и разблокировки: `OtpInput` или «Использовать резервный код» (`TextField`), `staff.mfa_invalid` — «Осталось N попыток…» по `attemptsLeft`, `0` — «доступ закрыт на час», ввод недоступен, фокус на «Ко входу»; 429 — отсчёт в кнопке, поле остаётся доступным (фокус не уходит на body), по концу отсчёта текст снят.
  - `/accept` — почта руками (из адреса не читается), пароль дважды (`validate.mismatch`), код из письма (`xxxxx-xxxxx`: `TextField` без `inputMode="numeric"`, `autoCapitalize="none"`, `spellCheck={false}`, `one-time-code`; уходит как введён — нормализует сервер); «Прислать код ещё раз» (`staffResendInviteSelf`, всегда 202, тот же код) — отсчёт 60 с; в теле принятия — всегда `locale` экрана (выше, «Язык до входа»).
  - `/setup-2fa` — секрет `staffMfaSetup` через `useQuery` (`staleTime: Infinity`, `gcTime: 0`, без повторов: каждый выпуск — новый секрет, StrictMode не дублирует), QR и секрет → `staffMfaConfirm` (`gcTime: 0`) → коды (копировать, `.txt` Blob-ом), «Я сохранил коды» → `staffRecoveryAck`; `409 staff.wrong_stage` — «уже подтверждён» → ack; ack ответил `wrong_stage`, а me всё ещё `setup` (секрет сброшен повторным принятием) — снова сканирование, один раз (второй — ошибка, без петли); `idempotency.replay_unavailable` — «Начать заново»; «Выйти» под карточкой (`useLogout`). Выпуск — `meta: ONE_SHOT` (`app/query.ts`): смена сотрудника его удаляет, а не перезапускает. Экран помнит, чья настройка на нём: me стал другим сотрудником (в другой вкладке прежний вышел, следующий принял приглашение и сканирует там) — секрет и коды прежнего сняты, свой секрет сам не выпускается (сжёг бы QR той вкладки): «продолжают в другой вкладке» + «Начать заново» — явный выпуск (повторное ревью 27.10, m2). Метка смены действует и на вернувшегося прежнего (A → B → A: его настройка тоже могла уйти в другую вкладку). Шаг снят сменой — фокус на заголовок. Так же и при новом монтаже, если вкладка увидела смену сотрудника без 401 (каркас A → стадия setup B; метка — `useStaffSwitched` из той же подписки `SessionProvider`, 401 её снимает): выпуск только по «Начать заново». Обычный путь (принятие приглашения в этой вкладке, перезагрузка, вход после 401) выпускает сразу. Без сессии шаги не рисуются (выход — ни секрета, ни выпуска). «Начать заново» (и после `replay_unavailable`) — фокус на заголовок страницы (`AuthLayout titleRef`, `tabIndex -1`), не на body.
  - `ReauthModal` (стоит в `AppRouter` поверх любой страницы) — открыт, пока ждёт `reauthBus`; `staffUnlock` → `resolve()` (ждущие запросы повторяются тем же ключом), блокировка, конец сессии и «Выйти» (`useLogout`) → `reject()`. Закрыть без разблокировки нельзя.
