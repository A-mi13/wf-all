# Админка (`apps/admin`)

Спека — `docs/superpowers/specs/2026-10-06-staff-admin-geo2-design.md` §9. Общие правила фронтов — `frontend.md`.

- **Структура:** `src/app/` — роутер, провайдеры, сессия, права, guard'ы; `src/ui/` — набор компонентов; `src/features/<раздел>/` — экраны; `src/api/` — клиент и мутации; `src/i18n/` — язык.
- **Компоненты** — только из `src/ui` (импорт `../../ui`); своих кнопок, полей, модалок, таблиц и состояний в `features` не заводить. Заглушки разделов до Task 15 (подтверждения, журнал) — `src/app/stubs.tsx` (`SectionStub` — раздел внутри AppShell).
  - Каркас — `AppShell` (`src/ui/shell`), его ставит роутер для стадии `active` (`ActiveShell` в `router.tsx`): меню из `NAV` (`src/app/nav.ts`), карточка «имя, роль · города» (`useAccountCard`, названия городов — `GET /v1/geo/cities?ids=`), переключатель языка в меню профиля, «Выйти» (`useLogout()` из `src/app/logout.ts`: `POST /v1/staff/auth/logout`, затем `session.afterLogout()` — вход без `return`: следующий сотрудник не попадёт в чужой раздел; стираются черновики форм (`clearDrafts()`) и кэш мутаций; `401` на выходе — так же; истёкшая сессия — по-прежнему с возвратом). Флаг «без return» живёт только во вкладке, где нажали «Выйти»: другие вкладки после 401 уходят на вход с `return` — осознанно, общий выход по вкладкам (BroadcastChannel) — по необходимости. Ширина < `breakpoint-mobile` — нижний таббар (до 4 разделов, открытых на телефоне) и «Ещё» (шторка: карточка, все разрешённые разделы, язык, «Выйти»). Счётчик пункта — проп `counts` по `path` (число) и `NavItem.countLabelKey` (подпись для читалки, `{count}`); запрос счётчика «Подтверждения» — фоновый, `...background()` (Task 15).
  - **Новый раздел:** путь — `paths.ts`; маршрут — ребёнок `shellRoute` в `router.tsx`; пункт в `NAV` — `{ path, labelKey, permission, icon, desktopOnly? }`. `permission` — ключ каталога (`null` — своё, любому активному). Пункта без права в меню нет, прямой адрес (и вложенные `/раздел/…`) — `ForbiddenState` сам AppShell; `desktopOnly: true` — на телефоне `DesktopOnlyState` (в таббар не попадает, в «Ещё» есть). Экран раздела проверку права не дублирует; страница начинается с `PageHeader` (единственный `h1`), вкладки — `Tabs` (управляемые, значение — search-параметр; счётчик — `count`, имя вкладки «Входящие 3»).
  - Списки — `DataTable` (`columns`, `rowKey`, данные — `{...infiniteTableProps(useInfiniteQuery(…))}` со страницами `{items, next_cursor}` и `getNextPageParam: (p) => p.next_cursor ?? undefined`): поиск (`search`, запрос уходит после паузы `SEARCH_DEBOUNCE_MS`; запоздавшее эхо отправленного значения набор не затирает), чипы (`chips`), раскрывающийся фильтр (`filters: { content, active }` — поля экрана; число заданных — в имени кнопки), сортировка (`sort` + `onSortChange`), «Показать ещё», «Показано N», «Сбросить фильтры» (`dirty` + `onReset`); сам показывает скелетон, пусто (`empty` — своё пустое без фильтров, «Очередь пуста»), ошибку с кодом и «Повторить» (`retrying` — занята, пока идёт перезапрос). Роли строк и ячеек — явные: на телефоне строки-карточки, подпись столбца в ячейке видна и слышна. Фильтры и сортировку держит экран (search-параметры маршрута).
  - Состояния: `EmptyState`, `ErrorState` (код для поддержки + «Повторить»), `LoadingRows` (скелетон), `OfflineBanner` (`useOnline`; стоит в AppShell), `ForbiddenState`, `DesktopOnlyState`, `RateLimitedState` (`retryAfter` из `ApiError`, отсчёт; повторный 429 с тем же значением — `key={error}`), `PendingApprovalNotice` (после `202`), `ConnectionErrorState` (стадия `error` сессии).
  - Примитивы: `Button` (`variant`: primary | secondary | danger | danger-outline | link; `size="lg"` — вход; `loading`; по умолчанию `type="button"`), `StatusChip` (`tone`, текст обязателен), `CountBadge` (0 не рисуется, >99 — «99+»), `Avatar` (инициалы, декоративный), `QrCode` (`value`, `label`; матрица — `uqr`, SVG-путь без inline-стилей, без сети), `useCountdown()` (`{ left, start(seconds) }` — отсчёт 429 по `retryAfter` и паузы повторной отправки; `start` с тем же числом перезапускает).
  - Формы — `Form form={useForm()} onSubmit={(v) => m.mutateAsync(v)}` и поля `TextField`, `PasswordField`, `SelectField`, `MultiSelectField` (`searchable`, `onSearch` — поиск на сервере), `CheckboxField`, своё поле через `Controller` + `FieldError`. Ошибка `onSubmit`: `validation.failed` → `body.<поле>` раскладывается по полям (текст `ui.field_errors.<код>`), остальное — `FormError` (`errors.<код>`, откат на `errors.internal`). Особые случаи (`attempts_left`, 429) — `onError` экрана, вернуть `true`. Текст ошибки по коду вне формы — только `useErrorText()` или `<FormError error={…} />`, своих откатов не писать.
  - `OtpInput` — код второго фактора: `onComplete(code)` один раз на полный ввод, после ошибки — `ref.current.reset()` (очистка, `onChange('')` — экран не отправит стёртый код — и фокус; пока ячейки `disabled` — фокус встанет, когда их включат); резервный код — обычный `TextField`.
  - Оверлеи `Modal`, `Drawer` (панель справа), `Sheet` (шторка снизу), `ConfirmDialog` (`confirmWord` — слово или почта, точное совпадение; `children` — поля над вводом слова, например причина, в `FormProvider` экрана — у диалога своя `<form>`; `error` — ошибка запроса внутри диалога, он не закрывается и введённое не теряет): `open` + `onClose` у экрана, фокус-ловушка, Esc (только верхний), возврат фокуса на открыватель (запоминается до `autoFocus` содержимого), блок прокрутки — внутри. `dismissible={false}` / `loading` — пока идёт запрос. `ConfirmDialog` на узком экране сам становится шторкой (`useIsMobile`, порог — токен `breakpoint-mobile`).
  - Тосты — `useToast().success|info|error(текст, { action })`: успех и справка исчезают через 8 с (`TOAST_HIDE_MS`, пауза при наведении и фокусе), ошибка — только руками. Живые области постоянные и без ролей (`aria-live` polite/assertive): `getByRole('alert')` в тестах экранов находит только их ошибки. Порядок: успехи и справки — над ошибками, внутри области — по появлению. При открытой модалке тосты входят в цикл Tab; закрыли тост с фокусом (кнопкой или `dismiss(id)`) — фокус туда, откуда пришли, иначе на верхний диалог по стеку оверлеев. `ToastProvider` стоит в `AppProviders`.
  - `Form` гасит повторную отправку, пока идёт первая; ошибка не от API — `errors.internal` на экране и `console.error`.
  - CSP admin-api (`style-src 'self'`): во всём `src` (кроме тестов) нет атрибута `style`, `<style>`, `dangerouslySetInnerHTML` и записи в `element.style` — только CSS Modules; цвета — только `var(--wf-color-*)`. Страж — `src/ui/csp.test.ts`.
- **Экраны входа** (`src/features/auth`, Task 13; вне каркаса, `AuthLayout`): стадия сессии → маршрут (`guard.ts`): без сессии — `/login` (и `/accept`), `mfa_pending` — `/login` шаг 2 (и после перезагрузки), `setup` — только `/setup-2fa`, `active` — `?return=` или стартовая. Экран сам не навигирует: успех мутации → `session.refresh()`, остальное делает роутер.
  - `/login`: шаг 1 — `staffLogin` (анонимная: `security: []`, без `Idempotency-Key`), `staff.invalid_credentials` — общий текст, 429 — отсчёт, отправка недоступна; шаг 2 — `FactorForm` (`staffVerifyMfa`), `401 auth.unauthenticated` (5 минут вышли) — шаг 1 с пояснением. «Другая почта или пароль» и «Ко входу» запоминают брошенную сессию (`sessionId` стадии `mfa_pending`): её шаг 2 больше не показывается, неудачный вход остаётся на шаге 1 с ошибкой.
  - `FactorForm` — второй фактор входа и разблокировки: `OtpInput` или «Использовать резервный код» (`TextField`), `staff.mfa_invalid` — «Осталось N попыток…» по `attemptsLeft`, `0` — «доступ закрыт на час», ввод недоступен, фокус на «Ко входу»; 429 — отсчёт в кнопке, поле остаётся доступным (фокус не уходит на body), по концу отсчёта текст снят.
  - `/accept` — почта руками (из адреса не читается), пароль дважды (`validate.mismatch`), код из письма (`xxxxx-xxxxx`: `TextField` без `inputMode="numeric"`, `autoCapitalize="none"`, `spellCheck={false}`, `one-time-code`; уходит как введён — нормализует сервер); «Прислать код ещё раз» (`staffResendInviteSelf`, всегда 202, тот же код) — отсчёт 60 с.
  - `/setup-2fa` — секрет `staffMfaSetup` через `useQuery` (`staleTime: Infinity`, `gcTime: 0`, без повторов: каждый выпуск — новый секрет, StrictMode не дублирует), QR и секрет → `staffMfaConfirm` (`gcTime: 0`) → коды (копировать, `.txt` Blob-ом), «Я сохранил коды» → `staffRecoveryAck`; `409 staff.wrong_stage` — «уже подтверждён» → ack; ack ответил `wrong_stage`, а me всё ещё `setup` (секрет сброшен повторным принятием) — снова сканирование, один раз (второй — ошибка, без петли); `idempotency.replay_unavailable` — «Начать заново»; «Выйти» под карточкой (`useLogout`).
  - `ReauthModal` (стоит в `AppRouter` поверх любой страницы) — открыт, пока ждёт `reauthBus`; `staffUnlock` → `resolve()` (ждущие запросы повторяются тем же ключом), блокировка, конец сессии и «Выйти» (`useLogout`) → `reject()`. Закрыть без разблокировки нельзя.
  - Черновики (`useDraft`) на экранах входа — только почта; пароли, коды, секрет, резервные коды — только в памяти экрана: ни storage, ни кэш Query после шага; мутации с ними (`staffLogin`, `staffAcceptInvite`, второй фактор, `staffMfaConfirm`) — `gcTime: 0`, переменные не живут в кэше мутаций дольше экрана. Подписи полей для e2e — ключи `auth.*`, страж `src/i18n/e2e-keys.test.ts`.
- **«Мой доступ»** (`src/features/me`, Task 14; `self`, `desktopOnly`): ключи запросов `['staff','my',…]` — не под `ME_KEY` (перечитывание сессии их не задевает).
  - Второй фактор (`getStaffMfa`): «N из 10 не использованы», при ≤ 3 — предупреждение; сами коды после выдачи не показываются. «Перевыпустить коды» — `Modal` только с `OtpInput` (M9: резервного кода нет ни полем, ни переключателем) → `RecoveryCodesPanel` (`features/auth`, общая с настройкой 2FA); окно не закрывается, пока запрос идёт (`useIsMutating` по `mutationKey`: сервер мог уже сжечь старые коды), коды — только в состоянии окна, `gcTime: 0`; конец отсчёта 429 стирает набранный код (как N1 `FactorForm`). «Потерял доступ» — раскрывающийся текст (`aria-expanded`).
  - Сеансы: устройство из UA (`deviceOf` → ключи `me.sessions.browsers|systems.*`, подписи — `useSessionLabel`), у текущего — «Текущий сеанс» без кнопки; «Завершить» и «Завершить все другие» — `onSettled` перечитывает список (и после `404 staff.session_not_found` — тост).
  - Смена пароля (*): `Controller` + `OtpInput` (без автоотправки) или резервный код — в теле ровно одно; `gcTime: 0` и `reset()` мутации после ответа (карточка остаётся на экране — иначе пароли жили бы в кэше мутаций); `password_invalid` / `mfa_invalid` с `attempts_left` — «осталось N», фактор стёрт; `attempts_left = 0` — `useLockout()` (тост «доступ закрыт на час» над роутером + `session.refresh()`).
- **«Роли и доступ»** (`src/features/staff`, Task 14; `staff.roles.read`, `desktopOnly`): матрица и «Правило двух рук» — из `getStaffRoles` (`twoHandsRules`: права с `dual`, не готовый текст), незнакомые роль и клетка — «сотрудник» и «—». «Кто имеет доступ» — только с `staff.accounts.read`; фильтры `q`/`status`/`role` — search-параметры `/staff` (`parseStaffSearch` в `validateSearch`, незнакомое отбрасывается, `replace`).
  - Права кнопок — `roles.ts` по `me.permissions` и роли цели (§2.5–2.6): выдача — `grant` / `grant_elevated`; смена роли — `roleChangePermission` (elevated → `grant_elevated`, роль или новый город → `grant`, только снятие городов → `revoke`); выключение — `revoke` / `revoke_admin` / `revoke_owner`; сброс — `access.reset` / `reset_elevated`; сеансы цели owner/admin — только при `grant_elevated` (не по `me.role`); незнакомая роль цели — без снятия и сброса. `allow` — «Сохранить/Выключить», `needs_approval` — «Отправить на подтверждение», `202` → `PendingApprovalNotice` в панели. Своя строка — «это вы», без «Управлять».
  - Приглашение — `Drawer`: роли только выдаваемые, города модератора — `CityField` (поиск на сервере `listGeoCities?q=` с паузой, подписи выбранных — по `ids`), модератор без городов — ошибка поля до запроса; `email_taken` / `city_not_found` — на поле. Черновик (`useDraft('/staff:invite')`: почта, имя, роль, города) пишется ТОЛЬКО по вводу (`form.subscribe`, `type === 'change'`), не при размонтировании — иначе форма, закрытая выходом из окна разблокировки, вернула бы черновик после `clearDrafts()`.
  - Панель сотрудника — `getStaffAccount`; переотправка (429 — отсчёт в кнопке), роль и города, сеансы и «Завершить все», сброс, выключение. Разрушающие — `ConfirmDialog` с почтой цели как показана (IDN — A-форма `xn--…`, не декодировать) и причиной `reasons.*` (+ комментарий, для `other` — обязателен); `confirm` = эта почта. Пока действие идёт, панель не закрывается; после ответа — инвалидация `['staff','accounts']` (список, карточка, сеансы); блок исчез с фокусом — фокус на панель.
- **Права** — только из `me.permissions` (`useCan`, `useDecide`, для многих прав разом — `usePermissionCheck` из `src/app/session.tsx`), не по роли: `allow` — сразу, `scoped` — в `me.city_ids`, `dual` — «можно запросить» (`useDecide` → `needs_approval`). Раздела без права нет в меню (`src/app/nav.ts`), прямой адрес — `ForbiddenState`. Решает всегда сервер.
- **Тексты** — только `messages/{ru,en}.json`, en — перевод, не пустая строка (D21). Подписи прав — `permissions.<ключ>`, действий подтверждений — `approvals.actions.<действие>`, ошибок — `errors.<код>`; стражи — `src/i18n/labels.test.ts`, `error-codes.test.ts`.
- **Пути** — только константы `src/app/paths.ts`; новый раздел — путь там, маршрут в `src/app/router.tsx`, пункт меню с правом в `nav.ts`.
- **Запросы** — `useApi()` (openapi-fetch, тот же origin, `credentials: 'same-origin'`). Клиент сам ставит `X-WF-Admin` на мутациях и бросает `ApiError {status, code, fields, retryAfter, attemptsLeft}` на любой не-2xx; `401 auth.reauth_required` — ждёт разблокировку (`reauthBus`) и повторяет запрос. Данные ответа — `unwrap(api.GET(…))` (`src/api/client.ts`), без `!` и `as`; ответу 204 `unwrap` не нужен.
- **Мутации** — только `useAdminMutation(fn(vars, idempotencyKey))`: ключ идемпотентности — один на действие, `retry()` повторяет с тем же ключом; сам клиент ключ не создаёт (M6). `networkMode: 'always'` — офлайн не копится.
- **Фоновые опросы** (счётчики, статус импорта) — только с `...background()` (возвращает лишь `{ headers }`): заголовок `X-WF-Background: 1` не продлевает сессию. `401 auth.reauth_required` фонового запроса, как и любого, открывает разблокировку (§9.3: через 20 минут бездействия вкладка показывает модалку, а не замёрзший счётчик); открыта уже — запрос ждёт её же, второй раз не открывает.
- **Черновики форм** — `useDraft(<путь маршрута>)` (sessionStorage); пароли и коды в черновик не класть.
- **Токены** — только `--wf-*`; `text-faint` — только плейсхолдеры и неактивные иконки (контраст), подписи — `text-subtle`; `text-ghost` — только disabled; `breakpoint-mobile` — ширина переключения раскладки (в `@media` — через `tokens.ts`).
- **Тесты** — `renderWithProviders(ui, { me })` / `providers({ me })` из `src/test/render.tsx` (me в кэше; `me: null` — тест сам мокает `GET /v1/staff/me`); экран, который ведёт стадия сессии, — `renderApp(path, { me, strict })` из `src/test/app.tsx` (всё приложение на memory history, `me.current` меняет ручка мока, `storageDump()` — проверка, что секретов нет в storage), ответы `me` — `src/test/me.ts`, ошибки — `problem()` из `src/test/problem.ts`. Компонент `src/ui` без API и сессии — `renderWithIntl(ui, { locale })` (язык и тосты, возвращает `user`); с `vi.useFakeTimers()` события — `fireEvent`: user-event зависает (RTL ждёт настоящий `setTimeout`); экран с MSW и отсчётом — `vi.useFakeTimers({ shouldAdvanceTime: true })` (иначе ответ мока и `findBy*` не дождутся), время — `act(() => vi.advanceTimersByTime(…))`. Телефон — `vi.stubGlobal('matchMedia', …)` с `matches: true` (без matchMedia раскладка широкая); каркас с модератором запрашивает `GET /v1/geo/cities` (названия его городов) — мок в тесте (`src/app/router.test.tsx`).
