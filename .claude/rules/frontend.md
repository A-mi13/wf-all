# Фронты

## Принципы (решение пользователя 28.10.2026; детали реализации — спека «UI-фундамент», `docs/superpowers/specs/2026-10-28-ui-foundation-design.md`)
Обязательны для каждого экрана веба и админки (и для спеки Flutter); ревьюер фронта проверяет их отдельным пунктом.
1. **Адаптивность** — каждый экран на 1440 / 768 / 390 px; таблицы на телефоне — карточки, панели — шторки; точки перелома — только токены.
2. **Компоненты** — используется ≥ 2 раз → компонент (`src/ui`, общее веба и админки — `packages/`); своего оформления в экранах нет.
3. **Понятность** — у каждого действия видимый результат, нет тупиков, у вложенного экрана — возврат к родителю.
4. **Только токены** — цвета, отступы, радиусы, тени, шрифты, длительности и кривые анимаций, точки перелома — `--wf-*` из одного `tokens.json` (веб, админка, Flutter); **две темы — светлая и тёмная** (по умолчанию — системная, переключатель «Система · Светлая · Тёмная»).
5. **Компактность** — плотность за счёт типографики, не пустых блоков; второстепенное — в подсказках и раскрывающихся блоках.
6. **Современность** — последние стабильные версии; CSS: container queries, `:has()`, View Transitions.
7. **Красота** — пиктограммы и иллюстрации только из своего набора (`design/14-Иконки`, стикеры); анимации осмысленные и выключаются при `prefers-reduced-motion`; графики — одна библиотека, раскрашенная токенами (выбирается при первой потребности).
8. **Доступность — WCAG 2.2 AA**: клавиатура, видимый фокус, контраст, подписи для читалки.
9. **Пять состояний у любых данных** — скелетон по форме будущего содержимого (глобально), пусто (иллюстрация + следующий шаг), ошибка с кодом и «Повторить», нет сети, нет прав.
10. **Всё состояние — в адресе** — вкладки, фильтры, сортировка, открытая карточка; F5, «Назад» и пересланная ссылка ничего не теряют.
11. **Обратная связь на каждое действие** — занятость кнопки, тост или ошибка у поля; разрушающее — подтверждение, обратимое — «Отменить» в тосте; неизвестный исход не повторяется вслепую. **Защита от потери**: уход с несохранённой формы, закрытие панели/окна с введённым — свой диалог подтверждения; F5 и закрытие вкладки — стандартный диалог браузера (свой невозможен) + черновики форм.
12. **Производительность** — ленивые маршруты, виртуализация длинных списков, у веба — бюджет Core Web Vitals.
13. **Единый словарь** — одно действие называется одинаково везде; числа, даты, деньги (минорные единицы + валюта) — только `Intl`; время — относительное («5 мин назад»), точное — по наведению.
14. **Скорость работы** (админка): командная палитра Ctrl/⌘+K (разделы, действия, поиск сущностей, недавнее), горячие клавиши со шпаргалкой по `?`; таблицы — закреплённая шапка, выбор столбцов, плотность, возврат на ту же позицию, массовые действия с числом затронутых и подтверждением; копирование id/почты в один клик; подсказки к терминам. Оптимистичный UI — только для безопасных обратимых мелочей, не для действий с аудитом и подтверждением вдвоём.
15. **Визуальная проверка** — витрина компонентов (Ladle, все состояния и обе темы) и сравнение скриншотов в Linux-CI; фронтовая задача в конце снимает свои экраны на трёх ширинах для ревьюера.

## Устройство
- Приложения не импортируют друг друга; общее — только `@wf/*` из `packages/` (eslint-plugin-boundaries). Пакеты не импортируют приложения — корневой `eslint.config.mjs`, `pnpm run lint:packages` в `packages:ci`. Клиент админского API — только в `apps/admin`.
- Клиент API — через `ApiProvider`/`useApi`; адрес — тот же origin (`/v1` проксирует dev-сервер: rewrites в `next.config.ts` → `WF_API_ORIGIN`, `server.proxy` в `vite.config.ts` → `WF_ADMIN_API_ORIGIN`; серверные, без `VITE_`/`NEXT_PUBLIC_`).
- Цвета, отступы, шрифты — только CSS-переменные `--wf-*` из `@wf/tokens`; `tokens.css` сгенерирован, руками не править.
- Темы: цвет в `tokens.json` — строка или пара `{dark, light}` → `light-dark(<светлое>, <тёмное>)`; тему выбирает
  атрибут `data-theme` корня (`light` | `dark` | `system`, без атрибута — тёмная: веб его не ставит). Акцент `accent` —
  только заливка; текст, линия, курсор — `accent-ink`, кольцо фокуса — `focus`, рамки полей — `border-control`
  (формат и роли — `design/03-токены.md`). Сборка не должна полифилить `light-dark()`: у админки — `build.cssTarget`
  (минимальные браузеры) и проверка `dist`; цвет темы в JS — из `tokens.ts` по теме, не `getComputedStyle`.
- Иконки и иллюстрации — только `@wf/icons` (`packages/icons`): `icons.json` — выгрузка артборда 14
  (`node design/tools/extract-icons.mjs`, руками не править), `icons.extra.json` — меню (`nav`) и дорисованные
  (`drawn`, каждая — строкой «дорисовано *» в `design/README.md`). Своих SVG-контуров в приложениях нет; пакет —
  данные, рендер — у приложения (в админке `Icon`/`Illustration`), цвет — классами по роли слоя, не атрибутами.
- Строки в компонентах — только через `useTranslations`; новый ключ — сразу в `ru.json` и `en.json`.
- Числа, деньги, время (принцип 13) — хуками, не `Intl`/`toLocale*` в экранах (в админке — `admin.md` «Даты и
  числа»; деньги — минорные единицы десятичной строкой, без float, точно и больше 2^53); общий словарь действий —
  `actions.*` (страж `vocabulary.test.ts`).
- Раскладка внутри страниц — container queries по ширине области страницы или панели, каркас — по окну; пороги
  `@container` — литералы из `tokens.container` (или `breakpoint`), их сверяет страж (`layout-css.test.ts` админки).
- Витрина (принцип 15) — Ladle, истории CSF рядом с компонентом; скриншоты сравниваются только в Linux-CI, эталон —
  артефакт последнего зелёного `main`, метка `visual-change` (CLAUDE.md «Проверки», `admin-ui.md` «Витрина»).
- Тест компонента — `renderWithProviders` (`src/test/render.tsx`) + MSW-моки из `src/test/server.ts`.
- Async Server Components Next — через Playwright (`apps/web/e2e`), Vitest их не рендерит.
- Экран по макету: исходник в `design/screens/NN-*.dc.html`, токены — `design/03-токены.md`.
- Next 16 ≠ знакомый Next: перед кодом веба читать гайд в `apps/web/node_modules/next/dist/docs/` (подгружается из `apps/web/CLAUDE.md` → `@AGENTS.md`).
