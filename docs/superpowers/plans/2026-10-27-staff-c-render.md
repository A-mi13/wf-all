### Task 3: admin-api (и воркер) ждут схему при старте

**Цель.** Миграции накатывает только `wf-api` (`migrate-then-api`); Render выкатывает сервисы одного коммита
независимо, и admin-api нового релиза может стартовать раньше наката — и до него отвечать 500 или ронять задачи на
отсутствующих колонках. Процесс без мигратора ждёт, пока версия схемы не дорастёт до вшитой в бинарник (R3). Воркер
получает то же ожидание — для локального запуска и будущего стенда с воркером.

**Риск:** A (порядок выкатки; ошибка — admin-api на старой схеме или вечный старт).

**Файлы.** Изменить: `backend/internal/platform/migrate/migrate.go` (+ тест), `backend/internal/platform/server/server.go`
или общий помощник старта (+ тест), `backend/cmd/admin-api/main.go`, `backend/cmd/worker/main.go` (+ тесты),
`backend/internal/platform/grants/grants.sql` (`goose_db_version`: `SELECT` ролям `api`, `admin`, `worker`; сейчас —
никому), `grants_test.go`, `backend/internal/platform/config/config.go` (`DB.SchemaWait`, переменная
`<PREFIX>_DB_SCHEMA_WAIT`, по умолчанию 10 минут; новый env-ключ — в `.env.example`, `.env` скриптом и таблицы
`docs/deploy-dev.md`).

**Интерфейсы.**
- `package migrate`: `func Latest() (int64, error)` — максимальная версия вшитых миграций.
- `func WaitSchema(ctx context.Context, db *pgxpool.Pool, want int64, timeout, poll time.Duration, c clock.Clock) error`
  — `SELECT max(version_id) FROM goose_db_version WHERE is_applied` раз в `poll`, пока не `≥ want`; таймаут — ошибка
  `ErrSchemaBehind` с текущей и нужной версией; база **новее** бинарника — не ошибка (старый инстанс при откате).
  Нет прав на `goose_db_version` (42501: первый деплой с этой правкой — права выдаст `migrate up` `wf-api`) или нет
  самой таблицы (42P01: пустая база) — считаются «схема отстаёт»: опрос до таймаута с одной записью WARN, а не
  ошибка сразу; прочие ошибки базы — ошибка сразу (повторное ревью планов, minor 11).
- Зовётся в сервере admin-api и в режиме воркера после подключения к базе, до старта HTTP и River; команды оператора
  и разовые команды воркера — без ожидания, ошибка сразу (их запускают руками).

**Почему 10 минут** (ревью планов, minor 15): `wf-api` и `wf-admin-api` собирают образ каждый своей сборкой Render (у
каждого сервиса свой билд из того же Dockerfile, с Node-стадией); сборки идут независимо и могут закончиться с
разницей в минуты, а `wf-api` накатывает миграции только после своего старта. 2 минут не хватило бы на разницу
сборок; 10 — запас, при этом порт не слушается и Render не переключает трафик на новый инстанс. Сколько Render ждёт
открытия порта при деплое, прежде чем считать его неудачным, — **проверить по документации Render**; если меньше 10
минут — `SchemaWait` подогнать под него и записать (деплой упадёт с понятной строкой, повтор — Manual Deploy после
деплоя `wf-api`).

**Тесты:** `TestLatest` (совпадает с номером последнего файла миграций), `TestWaitSchemaReady` (сразу), `TestWaitSchemaBehind`
(фейковые часы: версия ниже → ждёт, поднялась → успех; не поднялась за `timeout` → `ErrSchemaBehind` с числами),
`TestWaitSchemaNewer` (база новее → успех), `TestWaitSchemaNoPrivilege` (роль без `SELECT` на `goose_db_version` →
опрос; права выдали — успех; не выдали за `timeout` — `ErrSchemaBehind`), `TestWaitSchemaOtherError` (обрыв соединения →
ошибка сразу), `grants_test.go` (`api`, `admin`, `worker` — `SELECT` на
`goose_db_version`, без записи), `TestAdminAPIWaitsSchema` (cmd: база без последней миграции → процесс не слушает
порт до наката; по таймауту — код выхода 1 и понятная ошибка), `TestOperatorCommandNoWait` (команда `staff …` при
отстающей схеме — ошибка сразу).

**Подсадка.** Сравнение `>` вместо `≥` — `TestWaitSchemaReady` падает; без `SELECT` у роли — `TestAdminAPIWaitsSchema`
падает 42501.

## Решения плана

Ответы пользователя (раздел выше) — выше решений.

- **R1. Статика — внутри образа, каталог — из `render.yaml`.** Один образ (спека §12), `dist` админки в
  `/app/admin`; `ADMIN_STATIC_DIR` задаёт сервис, а не `ENV` образа: dev и тесты по умолчанию без статики (её отдаёт
  Vite). Цена — сборка `wf-api` включает Node-стадию и запускается правками админки. Отдельный Render static site
  отвергнут: другой origin запрещён спекой §5.2 (CSRF по `Origin`, cookie `__Host-`).
- **R2. `ADMIN_STAFF_SECRET_KEYS` — `sync: false`, ключ в base64url, копия у пользователя.** Командам оператора нужно
  то же кольцо (сверка ключей, шифрование кода); значение, сгенерированное Render, пришлось бы копировать из панели, а
  потеря или случайная перегенерация переменной обнуляет все секреты TOTP. base64url — потому что Git Bash (MSYS)
  переписывает значения окружения с ведущим `/` при запуске не-MSYS программ (флак e2e 27.10); `keys.Decode` принимает
  оба алфавита.
- **R3. admin-api ждёт схему (до 10 мин); `SELECT` на `goose_db_version` всем ролям.** Мигрирует только `wf-api`;
  сервисы одного коммита собираются и выкатываются независимо — иначе окно «новый код — старая схема». Альтернатива —
  мигратор в admin-api — потребовала бы строку подключения владельца во втором сервисе. Версия схемы не секрет.
- **R4. Окно остановки — 30 с (умолчание Render), бюджет процессов ≤ 25 с.** `maxShutdownDelaySeconds` на бесплатном
  тарифе не проверен — не задаётся; бюджет admin-api ужимается (сейчас 27 с без закрытия пула). Остановка relay
  воркера — со сроком (для локального запуска). Пулы — значения стенда в `render.yaml`, сумма — против
  `max_connections` Neon; при нехватке у воркера — предупреждение, не отказ.
- **R5. Swagger admin-api на стенде выключен** (`ADMIN_DOCS_ENABLED=false`): аллоулист выключен (R6), `/docs` был бы
  публичным справочником поверхности админки; для ручных проверок — локальный `./task dev`.
- **R6. IP-аллоулист на стенде выключен.** Спека §5.1 / спека бэкенда §8.4(в): аллоулист — только с закрытым origin
  (свой домен за своим Cloudflare с проверкой источника); на стенде IP — сигнал лимитов и повторного второго
  фактора, не авторизация; аллоулист верил бы заголовку CDN, который на стенде не проверяется (журнал плана A, 9b ⚠️).
  Решение — спека деплоя (прод).
- **R7. Лимит `staff_auth` по IP до загрузки сессии — без изменений.** За общим NAT исчерпанный лимит закрывает вход
  всем с этого IP (журнал плана A, 9b ⚠️, решение спеки R9/P7); на стенде сотрудников единицы. Переоценка — спека
  деплоя; оперативно — `ADMIN_RATE_LIMITS` (`staff_auth.ip=…`).
- **R8. SMTP без TLS — только Mailpit.** `none` с нелокальным хостом или с логином — отказ старта (Task 6): опечатка в
  переменной не должна отправить API-ключ Resend открытым текстом.
- **R9. Воркер на Render не заводится — отступление от спеки §12** (ответ Q1). Спека называет `wf-worker` (импорт
  geo) составом плана C; пользователь решил пока без него. Следствия: импорт — командой оператора; кнопка в админке
  ставит задачу «в очередь», отмена — на экране (план B, R22); relay событий и чистки платформы на стенде не
  исполняются (как и сейчас). Код воркера (ожидание схемы, срок остановки relay) готов к будущему запуску; значения
  стенда для воркера в `render.yaml` не пишутся, страж `TestRenderYAMLNoWorker` держит решение явным.
- **R10. Закрытый исходящий SMTP — стоп, а не обход** (ответ Q2): проверка — первым шагом выкатки; обходы (платный
  инстанс, HTTP API Resend) — только решением пользователя.
