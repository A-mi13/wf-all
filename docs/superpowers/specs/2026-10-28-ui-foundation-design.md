## 1. Цель и рамки

### 1.1. Зачем

Админка выросла из плана A как «рабочий минимум»: тёмная тема, разделы безопасности и справочников закрыты на
телефоне целиком, каждое состояние и каждая мелочь (копирование, время, подсказки) делаются экраном заново.
Дальше на админку ложатся ещё десяток разделов (модули игроков, команд, матчей, модерации). Фундамент нужен
**до** G9 (Task 20–22 плана B) и до модулей: всё, что повторяется, делается один раз в `src/ui` и `@wf/*`, а
экраны только собирают.

Итог этапа:
1. Две темы из одного `tokens.json` с проверенным контрастом; переключатель «Система · Светлая · Тёмная».
2. Админка адаптивна во всех разделах; «только с компьютера» — для отдельных действий, а не разделов.
3. Набор паттернов скорости работы: командная палитра, горячие клавиши, таблицы с плотностью и столбцами,
   «Отменить» в тосте, защита от потери, относительное время, копирование, подсказки к терминам.
4. Пять состояний данных и скелетоны — одним компонентом.
5. Витрина компонентов и сравнение скриншотов в CI; скриншоты экранов задачи для ревьюера.
6. Главная «Что требует внимания».

### 1.4. Термины

- **Пара** — значение токена для светлой и тёмной темы.
- **Чернила (ink)** — цвет текста, значка, линии на фоне поверхности; **заливка (fill)** — сплошной фон, на котором
  лежит текст своего цвета (`on-…`).
- **Действие только с компьютера** — действие, кнопки которого на узком экране заменены пометкой «только с
  компьютера»; раздел при этом открыт. Ограничение интерфейса, не защита: решает сервер.
- **Предпочтение** — настройка вида у этого браузера (тема, плотность, столбцы, недавнее); в адрес не попадает, в
  отличие от **состояния экрана** (вкладка, фильтры, сортировка, открытая карточка) — принцип 10.

## 2. Токены и темы

### 2.1. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где пары | В том же `contracts/tokens/tokens.json`: каждый цвет — объект `{ "dark": "#…", "light": "#…" }` | Один источник для веба, админки и Flutter (принцип 4); пара видна рядом, забыть вторую тему нельзя — страж |
| Как в CSS | `--wf-color-x: light-dark(<light>, <dark>)`; тема выбирается свойством `color-scheme` корня | Одна строка на токен, без дублирования блоков; `color-scheme` заодно красит нативные полосы прокрутки и автозаполнение (своего поля даты больше нет — §4.17) |
| Какая тема без атрибута | Тёмная (`:root { color-scheme: dark }`) | Веб и всё, что не выбрало тему, остаются как сейчас; светлая включается только явно (§2.4) |
| Переключение | `<html data-theme="system\|light\|dark">`: `system` → `color-scheme: light dark` (по `prefers-color-scheme`), `light`/`dark` — принудительно | Системная тема работает без JS и без мигания; JS нужен только для явного выбора |
| Одинаковые в обеих темах | Можно строкой (`"accent": "#C6F24E"`) — генератор пишет значение без `light-dark()` | Заливка акцента — фирменный цвет, не меняется |
| Тени и затемнение | Новые токены (`shadow-*`, `scrim`) вместо `color-mix(… var(--wf-color-bg) …)` в CSS; у тени геометрия одна на обе темы, по теме меняется только цвет | Тень от цвета фона в светлой теме — светлая на светлом, не видна; `light-dark()` принимает только цвета (I1) |
| Сборка | `build.cssTarget` админки задаётся явно: `chrome123`, `firefox125`, `safari17.5`, `ios17.5` — минимальные браузеры админки (записываются в `admin.md`): Firefox 125 — из-за Popover API (основа `Select` без запасного пути, §4.8), iOS 17.5 — админка открыта на телефонах, а с `ios16.4` в целях Lightning CSS снова ставит полифил (n1) | Иначе Lightning CSS (минификатор Vite 8, цели по умолчанию `baseline-widely-available` — Chrome 111) заменит `light-dark()` полифилом на `--lightningcss-*`: в dev — родная функция, в проде — полифил, который не проверяет ни один страж (I2) |

Поддержка `light-dark()` — Chrome 123, Firefox 120, Safari 17.5 (Baseline 2024); браузеры админки (Chromium и WebKit
e2e) её имеют. С явной целью сборки прод-CSS совпадает с dev: значение внутри незарегистрированного custom property
вычисляется в месте использования по `color-scheme` элемента (`color-scheme` ставится только на корне и наследуется).
Совпадение проверяет прод-проект живого e2e (§4.12, I3): вычисленный фон `body` по `data-theme` на собранной админке.
Веб (`apps/web`, Next) атрибут темы не ставит; его сборку цель админки не касается.

### 2.2. Структура `tokens.json`

```
{
  "color":     { "<имя>": "#RRGGBB[AA]" | { "dark": "#RRGGBB[AA]", "light": "#RRGGBB[AA]" } },
  "shadow":    { "<имя>": { "y": 24, "blur": 64, "color": { "dark": "#…AA", "light": "#…AA" } } },
  "font", "text", "space", "radius", "size", "breakpoint", "duration",   // структура прежняя
  "ease": "cubic-bezier(…)", "ease-exit": "cubic-bezier(…)",           // строки верхнего уровня, как ease сейчас
  "container": { "narrow": 480, "wide": 720 },                          // пороги container queries (§2.8)
  "density":   { "compact": { "row": 36 }, "normal": { "row": 48 } },
  "contrast":  [ ["<текст>", "<фон>", 4.5], ["selected-border", "pitch", { "light": 3 }], … ] // §2.6; норма — число (обе темы) или { dark?, light? } (только названные темы; поправка 10.11, U8)
}
```

Цвет — `#RRGGBB` или `#RRGGBBAA` (альфа нужна `scrim` и теням; Flutter читает ARGB). Тень хранится данными, а не
строкой CSS — Flutter собирает `BoxShadow` из тех же чисел; геометрия одна на обе темы, `light-dark()` — только вокруг
цвета: генератор пишет `--wf-shadow-overlay: 0 24px 64px light-dark(#0F171229, #0B0F0DCC)`. Страж `build.test.mjs`: у
каждого `--wf-shadow-*` за `light-dark(` следует цвет (`#`), не число. `ease-exit` — строка верхнего уровня рядом с
`ease`, переменная `--wf-ease-exit`. Имена токенов не меняются (P21 плана A: прежние имена и тёмные значения
остаются), добавляются новые (§2.3).

### 2.4. Светлая палитра

Выведена из тёмной: тот же зелёный оттенок нейтралей, та же иерархия текста (text → secondary → muted → subtle →
faint → disabled → ghost); поверхности: фон — чуть зеленоватый серый, карточка — белая, «вдавленное» — темнее фона
(роль та же, что у `surface-sunken` в тёмной). Статусы темнее и насыщеннее, их фоны — светлые оттенки. Макета
светлой темы нет: палитра — предложение этой спеки, **приёмка — скриншоты ключевых экранов в обеих темах
пользователю** (решение Б: «палитру показать скриншотами») до слияния группы UF1b; инструмент снимков
`admin:shots` (§5.4) поэтому делается раньше — в группе UF1a (§7), а не в UF3. Правка значений после показа не
меняет устройства — только числа в `tokens.json` (страж контраста перепроверит).

Веб (`apps/web`) атрибут `data-theme` не ставит и остаётся тёмным: значения тёмной темы те же. Перевод веба на две
темы — с его экранами, по тем же токенам.

### 2.7. Движение и плотность

| Токен | Значение | Где |
|---|---|---|
| `duration.fast` / `base` / `slow` | 120 / 200 / 400 мс (как есть) | нажатие, переключатель / шторка, панель, тост / смена вида (View Transitions) |
| `ease` | cubic-bezier(0.2, 0, 0, 1) (как есть) | появление |
| `ease-exit` **новый** | cubic-bezier(0.3, 0, 1, 1) | уход: закрытие панели и тоста |
| `density.compact.row` / `density.normal.row` | 36 / 48 | высота строки `DataTable` (§4.5) |

Генератор добавляет `@media (prefers-reduced-motion: reduce) { :root { --wf-duration-fast: 0ms; … } }` — переходы на
токенах выключаются сами. Что не сводится к длительности (мерцание скелетона, View Transitions), гасится своим
`@media` в компоненте; JS-анимации спрашивают `useReducedMotion()` (`src/ui/motion.ts`). На грубом указателе
(`pointer: coarse`) плотность «компакт» не применяется — строка не ниже `touch-min` (44).

### 2.8. Генерация и потребители

- `packages/tokens/scripts/build.mjs`: `buildCss` пишет `:root { color-scheme: dark; … }`,
  `:root[data-theme='light'] { color-scheme: light }`, `:root[data-theme='system'] { color-scheme: light dark }`;
  цвета и тени — через `light-dark()`; блок reduced motion. `buildTs` — тот же JSON (`tokens.color.bg.light`) и тип
  `ThemeName`. `build.test.mjs` дополняется: `light-dark(#F3F6F3, #0B0F0D)` у `bg`, три правила `color-scheme`, блок
  reduced motion; проверка «закоммиченные файлы совпадают» — как есть. Прежние проверки значений тёмной темы
  переписываются на `light-dark(…, #тёмное)` — смысл P21 («тёмные значения не тронуты») сохраняется.
- JS, которому нужен цвет текущей темы (будущие графики, `<meta name="theme-color">`), берёт его через
  `useThemeColors()` из `tokens.color.<имя>[resolved]` (`tokens.ts`, `resolved` — из `useTheme()`): точно и без DOM.
  `getComputedStyle` не годится — у незарегистрированного custom property он вернёт строку `light-dark(#…, #…)`, а не
  цвет (I2). Тест: при `resolved = light` — `#F3F6F3`, не строка с `light-dark`.
- **Точки перелома.** `breakpoint.mobile` (768) остаётся; добавляется `breakpoint.compact` (1024, §3.4). Пороги
  container queries — свои токены `container.*` (`narrow` 480 — ширина панели, `wide` 720), потому что контейнер
  перестраивается по своему содержимому, а не по окну. В `@media` и `@container` переменные не работают — число пишется
  литералом; страж `src/ui/layout-css.test.ts` (расширение V1): каждая ширина в `@media` — из `tokens.breakpoint`, в
  `@container` — из `tokens.container` или `tokens.breakpoint` (для `max-width` — минус 0.02).
- **Flutter (wf-native)** получает из `tokens.json`: цвета парами → `ColorScheme`/`ThemeExtension` светлой и тёмной
  темы (`ThemeMode.system` по умолчанию — тот же принцип), тени данными → `BoxShadow`, длительности и кривые →
  `Duration`/`Cubic`, `contrast` → свой страж на тех же парах, `density` и `size.touch-min`. Генератор Flutter пишется в
  wf-native по этому формату; формат `tokens.json` — контракт между репо, меняется только с записью в
  `design/03-токены.md`. Сегодня потребителя в wf-native нет (проекта Flutter там пока нет — `docs/versions.md`),
  поэтому смена `color` со строки на объект ничего не ломает; генератор Flutter сразу пишется под пары.

### 3.2. Механизм: действие, а не раздел, и устройство, а не ширина

**«Только с компьютера» определяется устройством, а не шириной окна** (решение пользователя 28.10 по ревью I7).
Ширина < 768 бывает и на компьютере: масштаб 200 % на ноутбуке 1280 px даёт 640 CSS px, узкое окно рядом с почтой —
столько же. Прятать там права — нарушение WCAG 1.4.10 Reflow («без потери функциональности») и расхождение с буквой
решения А («с компьютера» — про устройство). Поэтому два разных признака:

| Признак | Хук | Что решает |
|---|---|---|
| Ширина окна | `useIsMobile()` (< `breakpoint.mobile`), `useIsCompact()` (< `breakpoint.compact`) | только раскладку: таббар, полоса, карточки вместо строк, шторка вместо панели |
| Устройство | `useIsHandheld()` = `(pointer: coarse)` **и** ширина < `breakpoint.compact` | только «только с компьютера»: `ActionGate`, решения `staff.*` в «Подтверждениях», палитра, клавиши |

Компьютер при любом масштабе и ширине — все действия есть (в раскладке телефона). Планшет на 1024+ с пальцем —
действия есть (рабочее место). Телефон в горизонтальной ориентации (< 1024, палец) — пометка.

- Реестр `DESKTOP_ONLY_PERMISSIONS` (`src/app/desktopOnly.ts`) — права, действия по которым на карманном устройстве
  заменены пометкой: `staff.roles.grant`, `staff.roles.grant_elevated`, `staff.roles.revoke`, `staff.roles.revoke_admin`,
  `staff.roles.revoke_owner`, `staff.access.reset`, `staff.access.reset_elevated`.
- Решения подтверждений: **любое действие с префиксом `staff.`**, включая незнакомое будущее, — только с компьютера
  (как сейчас `a.action.startsWith('staff.')` в `ApprovalsList`: закрыто по умолчанию; таблица «действие → право»
  пропустила бы новое действие — m4).
- Компонент `ActionGate` (`src/ui`):
  `ActionGate({ permission: string | readonly string[], children, compact?: boolean })` — на компьютере рендерит
  `children`; на карманном устройстве (`useIsHandheld()`), если хоть одно право в реестре, — пометку
  `DesktopOnlyNotice` («Выдача и снятие прав — только с компьютера»; `compact` — одна строка с иконкой вместо блока).
  Пометка не кнопка и не `disabled`-кнопка: недоступное действие не попадает в Tab-порядок и не притворяется
  нажимаемым. В `ActionGate` передаётся право **самого действия**: «Завершить все сеансы» цели — `staff.sessions.revoke`
  (не в реестре), а не `grant_elevated`, от которого зависит только видимость блока сеансов цели-админа (`roles.ts`) —
  иначе блок пропал бы на телефоне вопреки §3.1 (m5).
- Палитра (§4.1) и горячие клавиши не предлагают на карманном устройстве действий из реестра.
- Страж `desktopOnly.test.ts` (`matchMedia` в тесте различает запросы ширины и указателя): ширина 390 + `coarse` — в
  `StaffDrawer`/`StaffPage` нет «Пригласить», «Сохранить роль», «Сбросить доступ», «Выключить», есть пометка и
  «Завершить все сеансы» — **в том числе у цели-админа** при `grant_elevated`; ширина 640 + `fine` (масштаб на
  ноутбуке) — кнопки есть; 1280 + `fine` — есть. Подсадки: убрать `ActionGate` вокруг выключения — падает; гейт по
  `useIsMobile` вместо `useIsHandheld` — падает случай 640 + `fine`.

4. **Сущности** — города (`listGeoCities?q=&limit=5`, право `geo.cities.read`), сотрудники (`listStaffAccounts?q=&limit=5`,
   `staff.accounts.read`), страны (локально из кэша `listGeoCountries`, `geo.countries.read`). Запросы — от 2 символов,
   после паузы `SEARCH_DEBOUNCE_MS`, отменяются новым вводом (`AbortSignal` TanStack Query); каждая группа показывает
   своё «ищем…»/ошибку строкой, не роняя палитру. Запрос по праву, которого нет, не уходит вовсе.

**Реестр команд.** `type Command = { id: string; group: 'section' | 'action'; labelKey: string; keywordsKey?: string;
icon?: IconName; permission?: string | null; desktopOnly?: boolean; shortcut?: string; run: (ctx) => void }`.
Команды объявляют модули рядом со своими экранами (`features/<раздел>/commands.ts`), `src/app/commands.ts` их
собирает; общие — «Сменить тему», «Сменить язык», «Горячие клавиши», «Выйти». Действие, которому нужен экран
(«Пригласить сотрудника», «Активировать город», «Запустить импорт»), — переход на раздел с search-параметром,
открывающим панель (`/staff?invite=1`, `/geo/cities?activate=1`): так оно работает и из адреса, и после F5.
`features/*/commands.ts` попадают в основной кусок сборки, поэтому **не импортируют экраны** (только `paths`, типы,
ключи локалей, хуки прав) — иначе ленивые разделы (§4.15) склеятся с основным куском. Страж
`src/app/commands.test.ts`: импорты файлов `commands.ts` — только из разрешённого списка модулей (m17).

**Нечёткий поиск — своё, не библиотека.** Локально ищется ~50 строк (разделы, действия, недавнее, страны); сущности
ищет сервер (`normalize_text`). Нужны: регистр и `ё`→`е`, NFKC, **раскладка** («ujhjl» → «город», «city» по
английским ключевым словам из `keywordsKey` при русском интерфейсе), ранжирование «совпадение с начала > с начала
слова > подпоследовательность», диапазоны совпадения для подсветки. Библиотеки (fuse.js 7.5.0, match-sorter 8.3.0,
uFuzzy 1.0.19) раскладку не делают, а остальное — ~80 строк: `fuzzyRank(query, items, { fields }) → { item, score,
ranges }[]` в `src/ui/palette/fuzzy.ts` с таблицей тестов (включая раскладку и `ё`).

**Доступность** — шаблон WAI-ARIA combobox + listbox: поле `role="combobox"` с `aria-expanded`, `aria-controls`,
`aria-activedescendant`; группы — `role="group"` с подписью; стрелки — по пунктам, Home/End, Enter — выполнить,
Esc — закрыть (поле не пусто — сначала очистить). Число результатов — в вежливой живой области («7 результатов»),
обновляется после паузы ввода. Подсветка совпадения — `<mark>`, не цвет-единственный-носитель.

**Недавнее** — `localStorage` `wf.admin.recent.<staffId>`: `{ kind, id, label, path }`, не больше 8. У сотрудника
хранится только `display_name`, не почта. Черновики живут в `sessionStorage` (`claimDrafts`/`clearDrafts`), недавнее —
в `localStorage`, поэтому механизм называется отдельно: `clearRecent()` в `useLogout` и `claimRecent(me.id)` в
`SessionProvider` при входе (стирает ключи `wf.admin.recent.*` других сотрудников) — по тем же событиям, что черновики
(m14). Принято: браузер закрыли без «Выйти» — имена коллег (без почт) лежат в `localStorage` до следующего входа в
этом браузере, где их сотрёт `claimRecent` другого сотрудника или перезапишет свой. Пункт, к которому пропал доступ
(права сняли), не показывается — фильтр по `navFor(me)` и праву сущности.

**Тесты:** открытие по Ctrl+K и ⌘K, не открывается из поля ввода только по `k`; разделы только разрешённые; действие
`dual` с пометкой; на телефоне нет приглашения; сущности — запрос только с правом, от 2 символов, после паузы,
последний ответ побеждает (гонка ответов); недавнее стирается при выходе; клавиатура и `aria-activedescendant`.
Подсадка: фильтр по праву снят — тест модератора (видит «Пригласить») падает.

### 4.2. Горячие клавиши

| Клавиши | Действие |
|---|---|
| Ctrl/⌘+K | палитра (работает и из поля ввода) |
| `/` | фокус в поиск страницы (`DataTable.search`); нет поиска — палитра |
| `g`, затем буква (≤ 1 с) | раздел: `g h` главная, `g a` журнал, `g r` роли, `g p` подтверждения, `g m` мой доступ, `g c` города, `g o` страны, `g i` импорт, `g v` версии, `g f` флаги |
| `?` | шпаргалка (`ShortcutsHelp`, `Modal`) |
| Esc | закрыть верхний оверлей (уже есть) |

- Клавиши — по `KeyboardEvent.code` (`KeyG`, `Slash`), а не `key`: работают в русской раскладке. В шпаргалке
  показывается символ по раскладке (`navigator.keyboard.getLayoutMap()`, где есть; иначе латиница).
- Не срабатывают: фокус в `input`, `textarea`, `select`, `[contenteditable]`, `[role=combobox]`, `[role=textbox]`;
  идёт ввод IME (`isComposing`); зажаты Ctrl/Alt/Meta (кроме своих сочетаний). Открыт модальный оверлей — не действует
  ничего, кроме Esc (закрывает верхнюю запись стека); Ctrl+K поверх модалки палитру не открывает (m15). «Открыт
  модальный» — есть модальная запись стека (§4.8): открытая подсказка или список `Select` на странице клавиши не глушат
  (R2-1).
- **Читалки и WCAG 2.1.4.** Односимвольные клавиши (`/`, `g x`, `?`) читалки в режиме обзора перехватывают сами — до
  страницы не доходят, конфликта нет; в режиме редактирования пользователь может нажать их случайно — поэтому в
  шпаргалке переключатель «Односимвольные клавиши» (по умолчанию включены; предпочтение в `localStorage`), Ctrl+K
  работает всегда. Это требование 2.1.4 (отключаемость), не опция.
- Устройство: `ShortcutsProvider` (в `AppProviders` под роутером) — один слушатель `keydown` на `document`;
  `useShortcut(combo, handler, { enabled, allowInInput })` регистрирует; конфликт регистраций одной комбинации —
  ошибка в разработке (`console.error`) и тест. Шпаргалка строится из реестра — устаревших строк в ней не бывает.

### 4.3. Пять состояний и скелетоны

`DataState` — единый вход экрана в данные (кроме `DataTable`, у которого состояния уже свои и он переводится на те же
части):

```
DataState<T>({ query: UseQueryResult<T>,
               skeleton: ReactNode,              // форма будущего содержимого
               isEmpty?: (data: T) => boolean, empty?: ReactNode,
               children: (data: T) => ReactNode })
```

| Состояние | Когда | Что видно |
|---|---|---|
| Загрузка | нет данных, идёт запрос | `skeleton` — появляется через 150 мс (быстрый ответ без мигания), обёртка `aria-busy`, для читалки «Загрузка…» один раз |
| Пусто | `isEmpty(data)` | `empty` (иллюстрация + следующий шаг, §4.4) |
| Ошибка | ошибка, данных нет | `ErrorState` (код и «Повторить»); 403 — `ForbiddenState`, 429 — `RateLimitedState`, 401 — общий механизм сессии |
| Нет сети | данных нет и запрос на паузе: `fetchStatus === 'paused'` (запросы — `networkMode: 'online'`, `app/query.ts`: без сети TanStack Query не шлёт и не даёт ошибки, а ставит паузу — m19) или сетевой сбой (`TypeError` fetch) | `NoNetworkState`: «Нет связи — покажем, как только появится», запрос продолжится сам при возврате сети |
| Данные есть | — | `children(data)`; фоновая ошибка перечитывания не прячет данные (баннер «нет сети» уже в каркасе) |

Скелетоны — `Skeleton.Text({ lines, width })`, `Skeleton.Block({ height })` (высота — токен `size.*`/`space.*`),
`Skeleton.Card()`, `Skeleton.Table({ columns, rows })`, `Skeleton.Form({ fields })`; готовые формы страниц собираются
из них в `features/*` рядом с экраном (`CityPageSkeleton`). Мерцание — CSS-анимация фона, при reduced motion —
статичный блок. Страж: экраны `features/*` не рендерят `LoadingRows`/«Загрузка…» вне `DataState`/`DataTable`
(поиск по исходникам, как `csp.test.ts`).

### 4.4. Пустое состояние с иллюстрацией

`EmptyState({ title?, text?, action?, tone?, illustration?: IllustrationName })` — к существующему добавляется
`illustration`: двухцветный рисунок из `@wf/icons` (§4.9) в размере 48–64, предмет — `text-muted`, акцент —
`accent-ink`, `aria-hidden` (смысл — в заголовке). Правило текста: что случилось + следующий шаг кнопкой («Городов
пока нет» → «Активировать город», «Очередь пуста» → «Посмотреть журнал»). Соответствие экранов и рисунков — таблица
в `design/README.md` (свисток — подтверждения, мяч — пустой поиск, поле — города, флажок углового — флаги, секундомер —
импорт). Стикеры достижений (`16-Стикеры-достижений`) — игровой язык игрока, в админке не используются.

### 4.5. Таблицы

Новое в `DataTableProps<T>` (всё необязательное — старые экраны работают без правок):

```
tableId?: string                       // ключ предпочтений (столбцы); без него выбор столбцов скрыт
stickyHeader?: boolean                 // по умолчанию true при rows > 20
columns[].hideable?: boolean           // можно скрыть (по умолчанию true, кроме первого)
columns[].priority?: 'high' | 'low'    // low — скрыт на 768–1023 и в карточке телефона под «Подробнее»
bulk?: {                               // массовые действия (флажки); не путать с режимом select (V1: выбор одной строки)
  selected: ReadonlySet<string>; onChange(next: ReadonlySet<string>): void;
  actions: BulkAction<T>[];
}
virtualize?: boolean | { estimateRow?: number }   // по умолчанию — при rows > 200
restoreKey?: string                    // ключ позиции прокрутки и фокуса строки (по умолчанию — путь + search)
```

```
BulkAction<T> = { id: string; label: string; tone?: 'default' | 'danger';
                  permission: (row: T) => string;        // право на ЭТУ строку (у выключения — по роли цели)
                  confirm: { title: (n: number) => string; word?: string };    // всегда с подтверждением
                  run: (row: T, idempotencyKey: string) => Promise<BulkOutcome>; concurrency?: number }  // по умолчанию 3
BulkOutcome = 'executed' | 'pending_approval'            // 200 / 202 (подтверждение вдвоём)
```

- **Режимы `select` и `bulk` взаимоисключающие** (m16): `select` (V1) — список выбора одной строки (`listbox`,
  `aria-activedescendant`, «Выбрать» в подвале); `bulk` — флажки и панель «Выбрано N». Таблица с обоими — ошибка
  разработки (тип не даёт). С виртуализацией в режиме `select` активная опция обязана быть в DOM: перед сменой
  `aria-activedescendant` — `scrollToIndex` виртуализатора.
- **Закреплённая шапка** — `position: sticky` внутри своего прокручиваемого контейнера: обёртка таблицы — область
  прокрутки по обеим осям высотой до низа окна (`max-block-size` от `100dvh` минус шапка страницы — через container
  query), иначе горизонтальная прокрутка обёртки ломает «липкость» к странице. Первый столбец закрепляется
  (`stickyFirstColumn`) у широких таблиц (матрица прав, флаги).
- **Фокус не закрыт (WCAG 2.4.11 Focus Not Obscured)** (I13): всё закреплённое, что добавляет фундамент, может накрыть
  фокус — шапка таблицы, первый столбец, подвал панели (V1), нижний таббар, тосты. Поэтому у каждой области прокрутки
  `scroll-padding-block-start` = `size.table-header` (у таблицы), `scroll-padding-inline-start` = ширина закреплённого
  столбца, `scroll-padding-block-end` у тела панели = высота подвала, у страницы на телефоне = `size.tabbar`; тосты
  встают вне подвала открытой панели, на телефоне — **снизу, над таббаром** (n5). Тост с «Отменить» сам не исчезает
  (§4.10), поэтому, пока он на экране, корень получает `data-toast-open` (запись атрибута, не стиля), и
  `scroll-padding-block-end` страницы на телефоне = `size.tabbar` + `size.toast` (новый токен: высота однострочного
  тоста с кнопкой; тост с «Отменить» на телефоне — однострочный, длинный текст — многоточие, полный — читалке); Esc при
  пустом стеке оверлеев (ни одной записи, в том числе подсказки — §4.8) закрывает новейший тост. Проверка — снимки истории «фокус на строке под шапкой после Tab снизу
  вверх», «последнее поле формы над подвалом», «фокус на последней строке при открытом тосте „Отменить“ (390)».
- **Выбор столбцов** — кнопка «Столбцы» в панели инструментов (рядом с «Ещё фильтры»), меню с флажками на `Popover`
  (§4.8 — верхний слой, `overflow` таблицы его не режет); хотя бы один видимый. Предпочтение — `localStorage`
  `wf.admin.table.<tableId>`; незнакомые id столбцов при чтении отбрасываются. На телефоне (карточки) кнопки нет.
- **Плотность** — одна на все таблицы: `compact | normal`, переключатель в меню «Столбцы» и в палитре; высота строки —
  `density.*.row`; на `pointer: coarse` — всегда `normal`.
- **Возврат на ту же позицию** — уходя в карточку и возвращаясь «Назад» (или общим «возвратом» V1), пользователь видит
  те же загруженные страницы (кэш `useInfiniteQuery` живёт `gcTime`), ту же прокрутку (TanStack Router
  `scrollRestoration` + `data-scroll-restoration-id` у контейнера таблицы) и фокус на строке, с которой ушёл
  (`activeRowKey` → фокус после восстановления). Перечитывание при возврате не сдвигает строк до окончания
  (как `useSettleDecision`: данные заменяются целиком, позиция — по ключу строки, не по индексу).
- **Массовые действия** (интерфейс сейчас, экраны — по мере появления). Флажок в строке и «выбрать видимые» в шапке
  (только загруженные строки: «выбрать всё по фильтру» требует серверной ручки — её нет); панель «Выбрано N» с
  действиями и «Снять выбор». Право — **на каждую строку** (`permission(row)` → `useDecide`): строка, где решение
  `deny` для всех действий, не выбирается (флажок недоступен, причина — подсказкой); действие в панели доступно, если
  разрешено хоть для одной выбранной, а подтверждение называет обе части («Выключить 3 учётки; ещё 2 вы выключить не
  можете — пропустим»). Действие всегда через `ConfirmDialog` с числом. Серверных массовых ручек нет (контракт
  заморожен) — исполнение по одной строке, `concurrency` параллельно, каждая со своим ключом идемпотентности; 429 —
  пауза по `Retry-After` и продолжение. **Итог — по видам** (I14): «Выполнено 3 · отправлено на подтверждение 2
  (`202`) · ошибка 1 · исход неизвестен 1» и список не выполненных с текстами `useErrorText`; «Повторить неудавшиеся» —
  4xx новым ключом, неизвестный исход (`isUnknownOutcome`) — тем же ключом, `202` не повторяется. После `202` —
  `useInvalidateApprovals()`. «Только с компьютера» — как у одиночного действия (`ActionGate` по праву строки). Риск
  исполнения — A (частичный отказ, повтор), план помечает.
- **Виртуализация** — `@tanstack/react-virtual` (3.14.23): DOM держит видимые строки ± запас; `aria-rowcount` и
  `aria-rowindex` у строк — читалка знает размер и позицию. Карточные списки (телефон, «Города и запуск») —
  `content-visibility: auto` + `contain-intrinsic-size` без JS (для строк таблицы не работает: содержание не
  применяется к внутренним элементам таблицы). Матрица флагов (до 2000 городов столбцами, Task 22) — виртуализация
  по горизонтали. CSP: виртуализации нужна запись положения в `element.style` — запрещено стражем `csp.test.ts`
  (не самой CSP: `style-src` не запрещает CSSOM). Решение — **один помощник** `setCssPx(el: HTMLElement, name: WfCssVar, px:
  number)` в `src/ui/cssVar.ts` (m-c): имя — типом `WfCssVar` (шаблонная строка с префиксом `--wf-`), значение — число,
  единица `px` дописывается внутри; это единственное место во всём `src`, где есть `setProperty`. Страж `csp.test.ts`:
  `setProperty`/`cssText`/`.style.` — только в `src/ui/cssVar.ts`; `setCssPx` вызывается только из `src/ui/popover/*`
  (вводит UF2a) и `src/ui/virtual/*` (добавляет UF2b); строки `anchor-name` и прочие нечисловые записи стилей
  невозможны по типу. Само оформление — в CSS Module. Правило `admin.md:22` («нет записи в `element.style`») получает это
  исключение тем же коммитом. Проверка под настоящей CSP — прод-проект живого e2e (§4.12, I3): собранная админка,
  отданная admin-api со `staticCSP`, обход разделов без `securitypolicyviolation`. **Подсадка — то, что CSP режет**
  (R2-3; запись через CSSOM, `element.style.color = …`, CSP не блокирует и подсадкой не годится): `setAttribute('style',
  'color: red')` на элементе, вставка элемента `<style>` или HTML со `style=` через `innerHTML` в сборке — сценарий
  обхода краснеет.

### 4.6. Состояние в адресе и сохранённые фильтры (задел)

- Всё состояние экрана — search-параметры с `validateSearch` (как `/audit`, `/staff`, `/approvals`, `/geo/cities`).
  Пробелы сейчас: открытая панель сотрудника (`/staff?account=<id>`), приглашение (`/staff?invite=1`), активация
  (`/geo/cities?activate=1`), раскрытая запись журнала (`/audit?entry=<id>`), страна (`/geo/countries?edit=<код>`,
  G9; не `country` — это фильтр списков, §15). Панель по адресу открывается и после F5.
- **История** (m9): открытие панели внутри приложения — `navigate` с `push` и меткой в `location.state`
  (`panel: true`); закрытие такой панели — `history.back()` (запись панели снимается, «Назад» после закрытия ведёт туда,
  куда ждут); панель, открытая глубокой ссылкой (метки нет), закрывается `navigate` без ключа с `replace: true`.
  Закрытие панели — это навигация, поэтому у вопроса «уйти без сохранения?» один владелец (N4, §4.11): закрытие после
  согласия идёт с `ignoreBlocker: true` (`router.history.back({ ignoreBlocker: true })` или `navigate({ …,
  ignoreBlocker: true })`) — блокировщик формы его не видит, второго вопроса нет. Исключений по ключу панели у
  блокировщика **нет** (R2-2): браузерная «Назад», жест iOS и системная кнопка Android с «грязной» панели меняют только
  её ключ, и именно этот уход должен спросить — `Overlay.dirty` его не перехватывает.
- **Временные ключи и возврат** (I6). Реестр `PANEL_SEARCH_KEYS` (`src/app/paths.ts`: `account`, `invite`, `activate`,
  `entry`, `edit`; ключ панели не совпадает ни с одним ключом фильтра ни на одном пути — страж, §15): (1)
  `BackMemoryProvider` (V1) запоминает адрес родителя **без** этих ключей — `BackLink` не
  откроет снова пустую панель; (2) уход из панели на другой путь (успех активации → страница города, «Открыть город»)
  — `navigate({ to, replace: true })`: запись `?activate=1` заменяется, браузерная «Назад» ведёт на список, а не в
  панель. Тест `CitiesPage.test`: активация → город → `BackLink` → списка с открытой активацией нет; то же браузерной
  «Назад». Подсадка: убрать вырезание ключей в `BackMemory` — тест падает.
- **Панель по адресу без права или с чужим id** (m10): ключ, для которого у сотрудника нет права (`?invite=1` без
  права выдачи, `?account=` без `staff.accounts.read`), экран игнорирует — панель не открывается, ключ снимается
  (`replace`); `?account=<id>`, на который сервер ответил 403/404, — панель с тем же состоянием, что у несуществующего
  («Сотрудник не найден»), без различения «нет» и «не ваш». Сервер решает, экран не раскрывает.
- Предпочтения (тема, плотность, столбцы, недавнее, односимвольные клавиши) в адрес не идут (§1.4).
- Сохранённые фильтры — не делаются. Задел: фильтр = search-параметры раздела, поэтому «сохранить» — это имя и
  `{ path, search }`; хранилище (локально или в профиле — тогда ручка контракта) решается вместе с экраном. Требование
  к экранам уже сейчас: ни один фильтр не живёт только в состоянии компонента.

### 4.7. Время, числа, деньги, словарь

- `RelativeTime({ value: string | Date, mode?: 'auto' | 'relative' | 'exact' })` → `<time dateTime={iso}>` с текстом
  «5 мин назад» (use-intl `relativeTime`) и точным временем («28 окт. 2026, 14:05:12, МСК» — пояс интерфейса): для
  читалки — скрытым текстом внутри `<time>` (слышно сразу, без подсказки), для мыши — `Tooltip` по наведению, для
  клавиатуры — та же подсказка, когда фокус внутри строки таблицы или карточки (`:focus-within`). Своей остановки Tab у
  `RelativeTime` нет: 50 строк журнала не дают 50 лишних остановок (m18); `title` не используется (недоступен с
  клавиатуры). `auto`: < 1 мин — «только что», < 7 дней — относительно, старше — дата. Обновление — общий таймер
  `useNow(granularity)`: одна подписка на минуту на всё приложение, в скрытой вкладке стоит.
- `useNumber()`, `useMoney()` (`src/i18n/format.ts`) рядом с `useDateTime()`: деньги — минорные единицы (int64,
  приходят строкой или безопасным целым) + ISO 4217 → **десятичная строка** собирается из целого без деления
  (`"123456"`, 2 знака → `"1234.56"`) и отдаётся `Intl.NumberFormat.format` строкой (принимает её точно) — без float
  (правило 2 CLAUDE.md, m13). Число знаков валюты — из того же справочника, что у бэкенда (экспонента ISO 4217), а не
  из CLDR (у части валют они расходятся); пока денег в админке нет — справочник появится с первым экраном сумм.
  Lint-правило (`no-restricted-syntax`) в `features/*`: `toLocaleString`, `toLocaleDateString`, `new Intl.*` — только
  через хуки.
- **Единый словарь.** Общие действия — ключи `actions.*` (`save`, `cancel`, `close`, `back`, `retry`, `archive`,
  `restore`, `delete`, `undo`, `copy`, `showMore`, `resetFilters`, `submitForApproval`); экран не заводит своего
  «Сохранить». Страж `src/i18n/vocabulary.test.ts`: (1) значение ключа `actions.*` в ru не повторяется под другим ключом
  (кроме явного списка исключений с причиной); (2) список запрещённых синонимов («Стереть», «Отмена» как действие,
  «Подтвердить» вместо «Отправить на подтверждение») не встречается. Терминология — глоссарий в
  `messages.glossary.*` (§4.8), он же источник подсказок.

### 4.8. Подсказка, термин, копирование

- **`Popover` — основа всего всплывающего** (подсказки, «i» терминов, меню «Столбцы», список `Select`, календарь):
  элемент с атрибутом `popover="manual"` (Popover API: Chrome 114, Safari 17, Firefox 125 — отсюда цели сборки §2.1)
  рисуется в **верхнем слое**, поэтому `overflow` предков — тело таблицы, тело панели — его не режет (I4; пузырь
  «внутри обёртки» обрезался бы у последней строки журнала и у края панели).
  `Popover({ anchor: RefObject<HTMLElement>, open, onClose, placement, kind: 'hint' | 'menu' | 'modal', label?, children })`.
- **Положение — один механизм: JS от якоря, числами** (N3). CSS anchor positioning не используется: уникальное
  `anchor-name` на каждый якорь без инлайн-стиля не записать, а при одинаковом имени у многих якорей спецификация берёт
  **последний** в дереве — все пузыри журнала встали бы к последней строке. Неявный якорь от вызывателя
  (`popovertarget`, `showPopover({ source })`) уникален, но не Baseline (Safari и Firefox — недавно или нет) — к нему
  вернуться, когда станет Baseline. Сейчас: при открытии и пока открыт (прокрутка любого предка — слушатель
  `scroll` с `capture`, `resize`, `ResizeObserver` якоря и самого пузыря — содержимое может вырасти после открытия; один `requestAnimationFrame` на кадр) `Popover` берёт
  `anchor.getBoundingClientRect()`, выбирает сторону (`placement`, переворот, если не помещается в окно) и пишет на
  **свой** элемент только числа `--wf-pop-x`/`--wf-pop-y`/`--wf-pop-max-h` через помощник `setCssPx` (исключение стража
  CSP для `src/ui/popover/*`, §4.5). Переменные живут на самом пузыре — у каждого свои, по построению уникальны. Якорь
  ушёл из видимой области прокрутки — подсказка (`hint`) закрывается, меню и список — остаются у края.
- **`Popover` в стеке оверлеев** (N2). Сейчас стек (`Overlay.tsx`, `stack.ts`) знает только `Modal`/`Drawer`/`Sheet`:
  Esc закрывает верхний оверлей, Tab ловит `trapTab` его панели, а `popover="manual"` Esc сам не обрабатывает. Поэтому
  `Popover` регистрируется в том же стеке, а **запись стека получает вид** (R2-1):
  `pushOverlay(id, panel, { modal: boolean })` — модальные: `Modal`, `Drawer`, `Sheet`, календарь (`kind: 'modal'`);
  немодальные: подсказка, «i», меню, список `Select` (`kind: 'hint' | 'menu'`). Сейчас `pushOverlay` для любой записи
  ставит блок прокрутки `body`, а `Overlay` ловит Tab только когда он верхний — с немодальной записью наверху это
  ломало бы страницу. Правило по виду:

  | Что | По каким записям стека |
  |---|---|
  | Esc | верхняя из **всех** — сначала список, меню, подсказка; следующим нажатием — панель. Обработавший делает `preventDefault`, `Overlay` закрывает только себя-верхнего (уже так) |
  | Блок прокрутки `body` (`data-wf-scroll-lock`) | только модальные: наведённая подсказка прокрутку не блокирует (иначе на Windows пропадала бы полоса прокрутки, страница сдвигалась и подсказка мерцала). Сдвиг при блоке от модальной записи (календарь на странице) гасит `scrollbar-gutter: stable` у корня (`html`, глобальный CSS админки, m-k) — место под полосу зарезервировано, якорь не сдвигается, `Popover` не нужен лишний замер |
  | Ловушка Tab (`trapTab`) | верхняя **модальная** запись: список `Select` наверху `Drawer` не снимает ловушку панели — Tab с последнего элемента остаётся в панели |
  | `topOverlayPanel()` (куда тосты возвращают фокус, §4.10) | верхняя модальная |
  | «Под модалкой» — горячие клавиши и Ctrl+K (§4.2): предикат `hasModalOverlay()` | есть хоть одна модальная запись; открытая подсказка Ctrl+K не глушит |
  | Esc для тоста (§4.5, §4.10) | только при **пустом** стеке (m-h): `ToastProvider` подписан на `document` раньше любого `Popover` и иначе закрыл бы тост тем же нажатием, что подсказку. Esc при подсказке закрывает подсказку, следующий (стек пуст) — тост |

  - **`kind: 'modal'`** (календарь `DateField`) — своя ловушка фокуса: пока он верхний модальный, `trapTab` работает по
    его панели, а не по панели `Drawer` под ним; на странице без оверлея (фильтры журнала) ловушка та же — модальный
    календарь не выпускает Tab, закрывается Esc или выбором, фокус возвращается на кнопку календаря.
  - **`kind: 'hint' | 'menu'`** — немодальные: у `Select` и подсказок фокус остаётся на вызывателе (у `Select` — на
    combobox, `aria-activedescendant`); у меню с фокусируемыми элементами («Столбцы») фокус может быть и внутри
    пузыря (m-o), Tab закрывает и уходит дальше в пределах ловушки модальной записи под ним. Слушатель
    `Overlay` подписан раньше и по Tab делает `trapTab` + `preventDefault`, поэтому немодальный `Popover` закрывается
    не по `keydown` с проверкой `defaultPrevented`, а по уходу фокуса с вызывателя (`focusout` якоря, фокус не внутри
    пузыря) — так он закрывается при любом владельце Tab (m-j).
  - **Нажатие внутри немодального пузыря не забирает фокус у вызывателя** (R4-1): `onMouseDown` на пузыре →
    `preventDefault()` (как в примере WAI-ARIA «select-only combobox»). **`pointerdown` не отменять** (m-n): отмена
    `pointerdown` гасит сам `mousedown` вместе с нашим обработчиком, а смену фокуса в Chromium не предотвращает — баг
    вернётся при зелёном страже jsdom. Исключение — `input`/`textarea` внутри пузыря (им фокус по щелчку нужен);
    поле поиска списка держать в якоре, а не в пузыре (m-o). Без этого `mousedown` по
    нефокусируемой `role="option"` уводит фокус с combobox, `focusout` скрывает пузырь до `click`, и выбор мышью
    теряется. У меню с фокусируемыми элементами («Столбцы», флажки) закрытие — по `focusout`, когда фокус покинул
    **и якорь, и пузырь** (`relatedTarget` проверяется по обоим), `preventDefault` на `mousedown` — тоже (Safari не даёт
    флажку фокус по щелчку). Страж (UF2a, `Select.test`): открыть список → `createEvent.mouseDown(option)` +
    `fireEvent` → `defaultPrevented === true`, combobox — `document.activeElement`; подсадка «без `preventDefault`» →
    тест красный (`pick` из `user-event` этого не ловит: `click` уходит на цель `mousedown` даже после скрытия).
  - **Открытие любого `Overlay`** (`ConfirmDialog` из панели, `ReauthModal` после 401 фонового запроса) закрывает все
    открытые `Popover` — иначе пузырь в верхнем слое висел бы поверх диалога в портале.
  - Тесты по группам (m-i). **UF2a** (`overlays.test.tsx`, `stack.test.ts`): `Select` в `Drawer` → Esc → список
    закрыт, панель открыта, фокус на combobox; второй Esc — панель закрыта; подсказка открыта на странице → у `body` нет
    `data-wf-scroll-lock`; список `Select` открыт в `Drawer` → Tab с последнего элемента панели → фокус остался в
    панели **и список закрыт** (m-j); подсказка открыта → `hasModalOverlay()` ложен; `topOverlayPanel()` при открытом
    списке в `Drawer` — панель `Drawer`; `TermHint` открыт → «Выключить» → `ConfirmDialog` → подсказки нет; календарь в
    `Drawer` и на странице — Tab циклится внутри календаря. **UF2b** (вместе с тостом «Отменить», n5): подсказка
    открыта, тост на экране → Esc закрывает подсказку, тост остаётся; второй Esc — тост. **UF4** (вместе с палитрой и
    `ShortcutsProvider`): подсказка открыта → Ctrl+K открывает палитру. Подсадки: `Popover` без `pushOverlay` — первый
    тест падает (закрылась панель); `pushOverlay` без учёта вида — тест блока прокрутки и тест Tab падают; гейт тоста
    «нет модальных» вместо «стек пуст» — тест UF2b падает (тост закрыт первым Esc).
- **jsdom** (n3): jsdom 30 Popover API не знает (`showPopover` — `undefined`). Прокладка в `src/test/setup.ts`:
  `showPopover`/`hidePopover`/`togglePopover` ставят и снимают атрибут-состояние `data-popover-open` и шлют событие
  `toggle` (как браузер); `matches(':popover-open')` — по нему же. CSS Modules в Vitest стилей не подключают, поэтому
  прокладка добавляет и тестовый `<style>` в `setup.ts` (CSP тестов не касается) с правилом
  `[popover]:not([data-popover-open]) { display: none }` (m-b) — тогда `toBeVisible` и дерево доступности отражают
  открытость. Тесты проверяют это состояние и видимость, а не факт вызова — «список открыт» не становится вакуумным.
  Страж прокладки: тест «закрытый `Select` — опций нет в дереве доступности» (без правила `display: none` он падает).
- `Tooltip({ content, children, placement? })` — на `Popover` (`kind: 'hint'`): подсказка по наведению и фокусу, Esc
  скрывает, наведение на саму подсказку её держит (WCAG 1.4.13); связь — `aria-describedby`. **Страж положения не
  вакуумный** (N3): в визуальный набор (§5.3) входит история «две подсказки разом — у первой и у средней строки
  `DataTable`» (подсказки открыты пропом `open`), и юнит-тест: два открытых `Popover` у разных якорей
  (`getBoundingClientRect` подменён) получают разные `--wf-pop-y`, каждый — от своего якоря. Подсадка: брать
  координаты общего (последнего) якоря — оба падают. История «подсказка у последней строки» остаётся — она про
  обрезку `overflow`.
- `TermHint({ term: GlossaryKey, children })` — термин в тексте с пунктирным подчёркиванием и кнопкой-«i»
  (переключаемая подсказка: нажатие открывает, текст — в живой области; WAI «toggletip»). Тексты — `glossary.<term>`
  (ru, en): «подтверждение вдвоём», «доступ в своих городах» (`scoped`), «ожидание / пилот / живой», GeoNames,
  «адрес в вебе» (slug), «резервные коды», «флаг функции». Страж `labels.test.ts` — каждый `GlossaryKey` есть в ru и en.
- `CopyButton({ value, label, display?: 'icon' | 'text' })` — `navigator.clipboard.writeText`; успех — значок
  «галочка» на 2 с и «Скопировано» в вежливой живой области (без тоста — не шумит); отказ (нет разрешения, не HTTPS) —
  значение выделяется в поле только для чтения и тост «Скопируйте вручную». Где: id в журнале и подтверждениях, почта
  сотрудника, адрес города, `geoname_id`, `job_id` импорта; секрет и коды настройки 2FA переводятся на тот же
  компонент.

### 4.10. «Отменить» в тосте и оптимистичный UI

- `useToast().success(text, { undo: () => Promise<void> })` — кнопка «Отменить» в тосте (существующий `action`
  становится частным случаем). `useUndoable(mutation, inverse)` — обёртка: выполнить → тост с «Отменить» → по нажатию
  обратный запрос **с новым ключом идемпотентности** (это новое действие, в журнале — отдельной записью) → тост
  итога; обратный упал с известным отказом (4xx) — тост-ошибка с текстом кода, исходное действие остаётся сделанным.
  **Исход обратного неизвестен** (`isUnknownOutcome`) — вслепую не повторяется: состояние цели перечитывается и тост
  говорит, что есть на самом деле («отменено» / «не отменено»); повтор отмены — только тем же ключом (общее правило
  `useAdminMutation`). Тест: обрыв ответа обратного → один запрос, перечитывание, тост по факту.
- **Тост с «Отменить» сам не исчезает** — как ошибка, закрывается руками, Esc (при пустом стеке оверлеев, §4.8) или
  следующим таким же тостом; на телефоне — однострочный, снизу над таббаром, с `scroll-padding` (§4.5, n5) (m12): 8 с с
  паузой на наведении не хватает пользователю клавиатуры и читалки, чтобы дойти до кнопки (WCAG 2.2.1). Отложенной
  отправки («сделаем через 8 с») нет — исход виден сразу, журнал честный.
- **Критерий обратимого** (все условия): обратное действие — одна ручка того же права; ответ `200` (не `202`, не
  «вдвоём») **и у обратного действия тоже**; нет внешних последствий, которые не отзываются (письмо, пуш, удаление
  данных, требование к клиентам); цель не изменилась кем-то ещё (при `409 *_stale` — тост «изменили — данные
  обновлены», без отмены). Сейчас подходят: «В архив»/«Вернуть» район, переименование района (у района нет `version`
  в контракте — `GeoDistrictPatch`; отмена — «последняя запись побеждает», чужую правку за эти секунды она перезапишет:
  принято, правка района редкая и видна в журнале — m11), флаг функции (обратное — тот же PATCH с актуальной
  `version`; `409 platform.flag_stale` — без отмены). **Не подходят:** включение страны (обратное — выключение — всегда
  вдвоём, `202`: «Отменить» создало бы запрос второму сотруднику — I5), сохранение версий приложения (подъём
  `min_version` — внешнее последствие: клиенты уже получили требование обновиться; `version` в `AppVersionsPut` нет —
  m11), приглашение, роль, сброс, выключение, решения подтверждений, активация города, удаление перевода (через
  подтверждение со словом).
- **Оптимистичный UI** — только предпочтения клиента (тема, плотность, столбцы, недавнее, свёрнутость блоков):
  применяются сразу. Серверная мутация — оптимистично только при всех условиях: идемпотентна, обратима по критерию
  выше, **не пишет в журнал действий**, не «вдвоём», ошибка откатывает вид. В админке сейчас все серверные мутации
  пишутся в журнал — значит, оптимистичных серверных нет (флаги — явно нет, план B Task 22); кандидаты появятся
  (отметка «прочитано», закрепление фильтра) и вносятся списком в `admin.md`.

### 4.11. Защита от потери

- `useLeaveGuard(dirty: boolean, opts?: { title?, text? })` — поверх `useBlocker` TanStack Router
  (`shouldBlockFn`, `withResolver`, `enableBeforeUnload: dirty`): переход внутри приложения (меню, ссылка, «Назад»,
  палитра, `g x`) при `dirty` — свой `ConfirmDialog` «Уйти без сохранения? Введённое пропадёт» с «Остаться»
  (фокус по умолчанию) и «Уйти»; F5 и закрытие вкладки — стандартный диалог браузера (`beforeunload`; свой
  невозможен) — и черновик `useDraft`, где он есть, вернёт введённое.
- `Overlay` (`Modal`, `Drawer`, `Sheet`) получает `dirty?: boolean`: Esc, клик по фону, «Закрыть» при `dirty` — тот
  же диалог (вложенный оверлей, стек уже есть). `ConfirmDialog` своего `dirty` не имеет (введённое слово не ценность).
- **Один вопрос на один уход** (N4). Панель в адресе (§4.6) закрывается навигацией, которую ловит и `useBlocker` формы
  в панели. Правило: закрытие панели своими средствами (Esc, фон, «Закрыть») спрашивает `Overlay.dirty`; после «Уйти»
  навигация закрытия идёт с `ignoreBlocker: true` — блокировщик формы её не видит. Других исключений у блокировщика
  нет (R2-2): уход, который `Overlay` не перехватывает, — браузерная «Назад», жест iOS, системная кнопка Android
  (меняют только ключ панели), меню, палитра, `g x` — спрашивает `useLeaveGuard`, ровно один раз; «Остаться» — адрес и
  введённое на месте.
- **Стенд для тестов ухода — browser history, не memory** (R3-1). Стандартный `renderApp` (`src/test/app.tsx`) стоит
  на `createMemoryHistory`, а в `@tanstack/history` 1.162.5 блокировщики опрашиваются только при `PUSH`/`REPLACE`:
  `back()` memory history просто сдвигает индекс — 0 вызовов блокировщика (проверено прогоном ревьюера). На нём тест
  «Назад» красный на верном коде, а подсадки неотличимы. Поэтому `renderApp(path, { history: 'browser' })` (новая
  опция стенда, UF2a): `AppRouter` получает `createBrowserHistory()` поверх окна jsdom — popstate и `go(-delta)` при
  отказе jsdom 30 исполняет (блокировщик вызван 1 раз, адрес вернулся). Все тесты ухода «Назад» и закрытия панели
  после «Уйти» — только на нём. Ловушка записывается в `.claude/rules/admin.md`, раздел «Тесты» («memory history не
  блокирует `back` — тесты блокировщика и закрытия панели на browser history») — пункт UF2a вместе с опцией стенда.
  Изоляция стенда (m-l): адрес выставляется `window.history.replaceState(null, '', path)` **до** создания истории;
  `history.destroy()` — в `cleanup` (иначе подменённый `pushState`, слушатели `popstate`/`beforeunload` и записи
  переходят в следующий тест); помощники `at()`/`back()` в этом режиме — через `window.location` и
  `window.history.back()`, а не через memory `history`.
- Тесты (UF2b, browser history):
  - «грязное» приглашение **открыто изнутри** (`renderApp('/staff', { history: 'browser' })` → «Пригласить», push) →
    ввод почты → Esc → «Уйти» → ровно один `ConfirmDialog`, панель закрыта (закрытие — `back` с `ignoreBlocker`),
    адрес без `invite`;
  - то же, **открыто глубокой ссылкой** (`renderApp('/staff?invite=1', { history: 'browser' })`, закрытие —
    `navigate` с `replace` и `ignoreBlocker`) → ровно один `ConfirmDialog`;
  - открыто изнутри → ввод почты → `window.history.back()` → `findAllByRole('dialog', { name: /Уйти без сохранения/ })`
    длиной 1 → «Остаться» → `location.search` = `?invite=1`, почта в поле, `queryAllByRole('dialog')` пуст;
  - «грязное» приглашение → пункт меню → ровно один вопрос.
  Подсадки: закрытие без `ignoreBlocker` — первые два теста видят второй диалог (оба варианта, не только глубокая
  ссылка); исключение для ключа панели в `shouldBlockFn` — третий тест видит ноль диалогов.
  «Ровно один диалог» проверяется на установившемся состоянии (m-m): `waitFor` с `getAllByRole(...)` длиной 1 после
  того, как адрес и панель пришли в конечное состояние, а не на первом `findAllByRole` — второй вопрос может
  отрисоваться на следующем такте.
- «Выйти» при несохранённом — тот же вопрос, но задаёт его **`useLogout` до POST** (m8): после выхода смена сессии
  уводит на вход редиректом из `beforeLoad`, а TanStack Router следует редиректу с `ignoreBlocker: true` — блокировщик
  маршрута там не спросил бы. Выход стирает черновики — так задумано (§9.3 спеки сотрудников).
- Разблокировка после бездействия (`401 auth.reauth_required`, `ReauthModal` поверх страницы) форму не теряет: перехода
  нет, всё в памяти. Сессия кончилась совсем (`401 auth.unauthenticated` → вход) — вернётся только то, что пишется в
  черновик `useDraft`; вопроса в обоих случаях нет (уход не по воле пользователя).
- `dirty` формы — `formState.isDirty` react-hook-form; после успешной отправки — сброс до перехода (иначе успех
  спросил бы «уйти без сохранения?»). Страж: тест формы — после успеха переход без диалога; с вводом — диалог;
  подсадка: `enableBeforeUnload: true` всегда — тест «чистая форма не вешает beforeunload» падает.
- Закреплённый подвал у `Modal`/`Drawer`/`Sheet` уже общий (V1, `footer`, отправка формы — `type="submit" form={id}`);
  фундамент добавляет к нему только `scroll-padding-block-end` тела (§4.5, фокус не под подвалом).

### 4.12. Тема: переключатель и хранение

**Где хранить — локально (`localStorage` `wf.theme`: `system | light | dark`), не в профиле сотрудника.**

| | Локально | В профиле (как язык, `updateStaffMeLocale`) |
|---|---|---|
| Экран входа, `/accept`, `/setup-2fa` | тема есть до входа | неизвестна до `getStaffMe` — вход всегда системный, после входа «перекрашивается» |
| Смысл выбора | свойство устройства: на телефоне тёмная, на рабочем мониторе светлая — нормально | одна на все устройства |
| Сервер | не нужен | язык хранится на сервере, потому что на нём письма; теме письма не нужны |
| Контракт | без правки | новая ручка или поле — контракт admin заморожен до конца плана B |
| Первый кадр | без мигания (скрипт до отрисовки) | мигание до ответа `me` |

Решение — локально, без привязки к сотруднику (тема не личные данные; один браузер — одна тема). Перенос в профиль —
только если пользователи попросят единую тему на всех устройствах, и не раньше конца плана B (§8.2).

**Применение без мигания.** `index.html`: `<html data-theme="system">` статически — системная тема работает без JS.
Явный выбор ставит `public/theme-init.js` — обычный (не модульный) скрипт в `<head>` до стилей: читает `wf.theme`,
ставит `document.documentElement.dataset.theme`; ошибка доступа к storage (приватный режим) — остаётся `system`.
Отдельный файл, а не инлайн: CSP admin-api — `script-src 'self'`. Сборка Vite кладёт файл из `public/` как есть.
Файл верхнего уровня admin-api отдаёт с `no-cache` (сверка с сервером на каждой загрузке — один короткий 304 до первого
кадра; принято, m25) и тем же `staticCSP` — случай в `backend/internal/httpapi/admin/static_test.go`.
Скрипт кладёт разбор значения в глобал (`window.__wfTheme = { parse }`); юнит-тест читает текст файла, исполняет его
в jsdom и проверяет `parse` (незнакомое и пустое — `system`) и установку атрибута (m25).

**Проверка на собранной админке — прод-проект живого e2e** (I3). Живой e2e сейчас поднимает Vite dev, который CSP
не ставит, а статику admin-api выключает (`e2e/env.ts`, `ADMIN_STATIC_DIR` пустой) — на нём `theme-init.js`, полифилы
сборки и CSP не проверяются. Новый проект Playwright `prod` (в `./task admin:e2e`, Chromium): `vite build` → admin-api
отдаёт сборку через `ADMIN_STATIC_DIR` с настоящим `staticCSP`. Сценарии: (1) `wf.theme = light` в storage → первый
снимок страницы входа светлый (`getComputedStyle(body).backgroundColor` = светлый `bg`), `system` + эмуляция
`prefers-color-scheme: dark` — тёмный; (2) обход всех разделов под сотрудником без единого `securitypolicyviolation`
(слушатель на странице, список нарушений — в отчёте); (3) вычисленный фон `body` совпадает с `tokens.color.bg[тема]`
для обеих тем (ловит расхождение dev ↔ прод CSS, I2). Подсадки: `setAttribute('style', 'color: red')`, вставка
`<style>` или `innerHTML` со `style=` в сборке — (2) падает (CSSOM-запись `element.style.*` CSP не режет — такая
подсадка вакуумна, R2-3);
`theme-init.js` убран из `index.html` — (1) падает.

**Устройство.** `ThemeProvider` (в `AppProviders`): `useTheme() → { theme: 'system' | 'light' | 'dark',
resolved: 'light' | 'dark', setTheme }`; `resolved` — по `matchMedia('(prefers-color-scheme: dark)')` с подпиской;
`setTheme` пишет storage и `dataset.theme` (это не `element.style` — страж CSP не задет); событие `storage` —
синхронизация вкладок. `<meta name="theme-color">` — две метки с `media` для системной темы, при явном выборе
`content` — из `useThemeColors()` (значение из `tokens.ts`, §2.8).

**`ThemeSwitch`** — `Segmented` с `label` «Тема» и тремя сегментами: значок (монитор / солнце / луна — дорисованные
иконки `@wf/icons`, §4.9)
+ имя для читалки «Система», «Светлая», «Тёмная» (`name` начинается с видимого текста — у значка видимого текста нет,
поэтому `title` и подпись в шпаргалке; WCAG 2.5.3 к значкам без текста не применяется). Место — в карточке
сотрудника рядом с «RU · EN» (V1: `accountActions`); раскладка карточки — ниже, в «Тестах»; в шторке «Ещё» и на
экранах входа (`AuthLayout`, в углу справа от бренда рядом с переключателем языка «RU · EN» — поправка 10.11, решение пользователя: язык до входа — выбор на устройстве `localStorage[wf.locale]`, после входа главнее `me.locale`) — тот же компонент. Команда палитры «Тема: светлая/тёмная/
системная». Смена темы — мгновенно, без анимации (reduced motion не нужен).

**Тесты:** `ThemeProvider.test` (по умолчанию `system`; выбор пишет storage и атрибут; storage недоступен — не
падает; событие `storage` из другой вкладки применяется), `ThemeSwitch.test` (`aria-pressed`, имена), `theme-init`
(выше), прод-проект e2e (выше). Подсадка: `setTheme` без записи в storage — тест «после перезагрузки» падает.
Ширина ряда карточки: ревью V1 (m3) посчитало, что «Sign out» уже на грани колонки (≈ 90 px при сегментах 40 px, 82 px
на `pointer: coarse`); с темой ряд не помещается заведомо (язык 82 + тема ≥ 98 + зазор > 186 px карточки). Раскладка:
язык и тема — каждый своей строкой (или одной, если по снимкам помещаются), «Выйти» — последней строкой во всю
ширину; проверка — снимки EN на трёх ширинах.

### 4.13. Главная «Что требует внимания»

Маршрут `/` (`paths.root`) внутри каркаса — первый пункт меню «Главная» (`permission: null`, иконка дома) и
**стартовая страница после входа для всех** (решение пользователя 28.10): `startPath` → `paths.root` (сейчас там
редирект на первый раздел). Переход по ссылке на конкретный экран (`?return=` — например, из письма или после
истёкшей сессии) по-прежнему важнее главной. Только существующие чтения — контракт не меняется.

| Индикатор | Право | Откуда | Что считается вниманием |
|---|---|---|---|
| Входящие подтверждения | `self` | тот же счётчик `useIncomingApprovalsCount()` | > 0 — «N ждут вашего решения» (на карманном устройстве, `useIsHandheld`, по `staff.*` — «решать с компьютера») |
| Мои запросы | `self` | `listApprovals?box=mine&status=pending&limit=100` | > 0 — «N ждут второго сотрудника», ближайший срок — `RelativeTime` |
| Импорт GeoNames | `geo.imports.read` | `listGeoImports?limit=5` | последний по стране упал или идёт дольше 30 мин — «Импорт RU упал 2 ч назад» |
| Города в ожидании | `geo.cities.read` | `listGeoCities?status=waitlist&limit=100` | > 0 — «N городов ждут запуска» (модератор — свои, сужает сервер) |

Под индикаторами — **список дел** (`TodoList`): строки из тех же данных со ссылкой-действием («Разобрать 3 запроса»
→ `/approvals`, «Открыть импорт RU» → `/geo/imports?country=RU`, «Посмотреть города в ожидании» →
`/geo/cities?status=waitlist`) и личное: «Осталось 2 резервных кода» (`getStaffMfa`, ≤ 3) → `/me`. Пусто — иллюстрация
и «Всё спокойно».

- `AttentionTile({ title, value: number | null, cap?: number, tone, href, state: 'loading' | 'error' | 'ready',
  onRetry, more?: boolean })` — при `limit=100` число больше 100 не придёт: «99+» показывается, когда строк ≥ 100
  **или** у ответа есть `next_cursor` (`more`; у API нет общего счёта, m7); ошибка одной плитки — «не загрузилось · Повторить»
  в плитке, остальные живут; плитки без права не рендерятся и не запрашивают. Вся плитка — ссылка (одна цель, имя =
  заголовок + число).
- Опрос: счётчик подтверждений уже опрашивается (`background()`, 60 с); остальные — при открытии и возврате во
  вкладку, без интервала (база Neon не будится зря). Все чтения главной — `...background()`: открытая главная не
  продлевает сессию.
- Порядок плиток фиксирован (не «по важности»): место плитки не прыгает между заходами.
- Тесты: каждая роль видит только свои плитки (модератор — без импорта); плитка с ошибкой не роняет остальные;
  100 строк → «99+», 99 строк с `next_cursor` → «99+», 99 без курсора → «99»; запросы с `X-WF-Background: 1`; вход без
  `return` — главная, с `return` — указанный экран. Подсадка: плитка импорта без проверки права — тест модератора
  (неописанный запрос MSW) падает.

### 4.15. Переходы и ленивые маршруты

- **View Transitions** — переходы «список → карточка» (город, сотрудник) и смена вкладок; включаются через
  `viewTransition` навигации TanStack Router (сверить API версии 1.170 в плане). Нет API (старый браузер) —
  мгновенный переход; reduced motion — `::view-transition-group(*) { animation: none }`. Имя перехода общего
  элемента — **одно статическое** (`view-transition-name: wf-entity` у класса `.vtSource`, который ставится только на
  нажатую карточку перед переходом, и у заголовка страницы назначения): уникальные имена на каждый элемент
  требовали бы инлайн-стилей (CSP). Длительность — `duration.slow`, кривая — `ease`.
- **Ленивые маршруты** — каждый раздел `features/<раздел>` — отдельный кусок (`lazyRouteComponent`/`.lazy()`
  TanStack Router); экраны входа и каркас — в основном куске (первый экран без ожидания). Предзагрузка по намерению
  (`defaultPreload: 'intent'` — наведение и фокус на пункте меню). Пока кусок грузится — скелетон раздела (§4.3), ошибка
  загрузки куска (вышла новая сборка) — `ErrorState` с «Обновить страницу».

### 4.16. Свой выпадающий список `SelectField` (решение пользователя 28.10, п. 8 V1)

Нативный `<select>` уходит **отовсюду**, в том числе на телефоне: раскрытый список рисует браузер (системное колесо,
чужой вид, светлый список в тёмной теме) — это нарушает принципы 4 и 7. 24 места в экранах (страны, регионы,
статусы, роли, фильтры) переводятся без правки экранов: API `SelectField` (`options`, `placeholder`, `rules`) не
меняется, меняется устройство.

- `Select` (`src/ui/form/Select.tsx`) — шаблон WAI-ARIA «select-only combobox»: кнопка `role="combobox"`
  (`aria-expanded`, `aria-controls`, `aria-activedescendant`, подпись поля — `aria-labelledby`) и `role="listbox"` с
  `role="option"` (`aria-selected`). Клавиатура: ↓/↑/Home/End, Enter/Space — выбрать, Esc — закрыть без выбора,
  ввод букв — переход к опции на эту букву (typeahead), Tab — закрыть и уйти. Фокус остаётся на кнопке.
- **Широкий экран** — список на `Popover` (§4.8, верхний слой: тело панели и таблица не режут), под полем, переворот у
  края окна. **Телефон** (`useIsMobile`, по раскладке) — список в `Sheet` снизу в нашем стиле: заголовок — подпись поля,
  крупные строки (`touch-min`), выбранная — галочкой; при > 10 опций — поле поиска сверху; выбор закрывает шторку.
- Длинные списки (страны ~250): в UF2a — **без виртуализации** (250 опций в DOM — норма, прокрутка к активной —
  `scrollIntoView({ block: 'nearest' })`); виртуализация списка `Select` с `scrollToIndex` активной опции — в UF2b,
  вместе с `@tanstack/react-virtual` и исключением CSP `src/ui/virtual` (n2), если замер покажет нужду. Пустое значение
  и `placeholder` — опция «не выбрано», если поле необязательное.
- Список — `Popover` `kind: 'menu'` в стеке оверлеев (§4.8): Esc закрывает только список (`preventDefault`), панель
  под ним остаётся открытой; шторка телефона — обычный `Sheet` стека.
- Формы: `SelectField` — `Controller` react-hook-form, `validation.failed` по полю — как сейчас. `MultiSelectField`
  (план A, уже свой) переводится на тот же `Popover`/`Sheet`.
- **Тесты.** ~37 вызовов `user.selectOptions` в 9 файлах → общий помощник `pick(user, field, optionName)`
  (`src/test/pick.ts`: открыть combobox, выбрать option по имени); `Select.test` — клавиатура, typeahead, Esc, телефон —
  шторка, `aria-*`. Страж `controls.test.ts` (V1) дополняется: `<select>` запрещён и внутри `src/ui` (после перевода).
- **Живой e2e** (решение пользователя 28.10): `e2e/staff.spec.ts` (`selectOption` роли приглашения) переписывается на
  клик по `combobox` и `option` (по подписям из `KEYS`); правило `admin.md` «роль приглашения — нативный `<select>`»
  снимается, вместо него — «роль приглашения — `combobox` + `option`». Выбирается мышью значение **не по умолчанию**
  (например, «Модератор»), и итог сверяется — браузерный страж R4-1 (jsdom выбор мышью по координатам не проверяет).

### 4.17. Свой календарь `DateField` (решение пользователя 28.10, п. 8 V1)

`TextField type="date"` (браузерный календарь: чужой вид, неделя по настройке ОС, а не языка интерфейса) заменяется
своим `DateField`; значение — по-прежнему строка `YYYY-MM-DD` (фильтры периода журнала, `toAuditQuery` не меняются).

- Поле ввода даты текстом в формате языка интерфейса (маска по `Intl.DateTimeFormat#formatToParts`) + кнопка
  «Открыть календарь» (иконка календаря, §4.9) → диалог-календарь по шаблону WAI-ARIA «Date Picker Dialog»: сетка
  `role="grid"`, стрелки — дни, PageUp/PageDown — месяцы, Shift+PageUp/PageDown — годы, Home/End — начало и конец
  недели, Enter — выбрать, Esc — закрыть; заголовок месяца — живая область. На широком экране — `Popover`
  `kind: 'modal'` (`aria-modal`, своя ловушка фокуса в стеке оверлеев — и внутри `Drawer`, и на странице без оверлея;
  Esc закрывает только календарь; фокус после закрытия — на кнопку календаря; §4.8, N2), на телефоне — `Sheet`.
- **Первый день недели — по языку интерфейса** через `Intl`: `new Intl.Locale(locale).getWeekInfo().firstDay` (или
  свойство `weekInfo` — в части движков); где API нет — запасная таблица для наших языков по тем же данным CLDR
  (`ru` — понедельник; `en` — по стандарту языка, CLDR для `en` — воскресенье). Названия дней и месяцев — `Intl`.
  Правило страны (`week_start` в справочнике) к интерфейсу админки не относится.
- `min`/`max` (например, «по» не раньше «с» — правило фильтра журнала) — недоступные дни в сетке, `aria-disabled`.
- Тесты: `ru` — первый столбец «пн», `en` — «Sun»; клавиатура по шаблону; ввод текстом ↔ выбор в сетке дают одну
  строку `YYYY-MM-DD`; пояс не сдвигает дату (дата — без времени). Подсадка: первый день недели из `0` всегда — тест
  `ru` падает.

### 5.3. Сравнение скриншотов в Linux-CI: эталон — последняя зелёная сборка `main`

**Решение пользователя 28.10: эталоны в репозитории не хранятся вообще** (ни в git, ни в Git LFS). Эталон — снимки
последнего зелёного прогона `main`, подходящего к базе PR (тот же вид, что у базы — ниже), сохранённые артефактом
GitHub Actions; намеренное изменение вида становится новым
эталоном само после слияния в `main`. Ручного обновления эталонов нет.

**Что снимается** (I12, «если недорого»): не каждая история, а **ограниченный набор** — истории с меткой `visual: true`
в метаданных (ключевые состояния компонентов: кнопки, поля, `Select`, календарь, таблица, состояния, тосты, оверлеи,
палитра, карточка каркаса) и 6–8 ключевых экранов режима `shots` (§5.4: вход, главная, журнал, «Роли и доступ»,
«Города и запуск», страница города). Снимок — **корня истории** (`locator.screenshot`), а не страницы 1440 px; три
ширины (390 / 768 / 1440) — только компонентам с раскладкой и экранам, остальным — одна. Темы — обе. Прочие истории
в CI проходят **дымовой прогон** без картинок: история отрисовалась, нет ошибок в консоли (так страж §5.2 ловит
сломанную историю без роста набора). Оценка: ~120–200 PNG по 5–40 КБ → **3–8 МБ на набор**; job — 4–8 минут
(образ ~1–2, сборка витрины ~1, снимки ~2–4). Порог для вопроса пользователю: набор > 20 МБ или job > 12 минут.

**Как устроено — отдельный workflow `.github/workflows/admin-visual.yml`** (N1). В `admin.yml` job жить не может: у
`admin.yml` фильтр `paths` на уровне workflow (`apps/admin/**`, `packages/**`, `backend/**`…), и коммиты в `main` по
`docs/`, `design/`, `.claude/` (большинство в этом репо) его не запускают — эталона «для базы PR» почти никогда не было
бы, сравнение пропускалось бы, и регрессия тихо становилась бы эталоном. Поэтому:
- `admin-visual.yml` — **без `paths`** у обоих триггеров: `push` в `main` и `pull_request` с
  `types: [opened, synchronize, reopened, labeled, unlabeled]` (метка `visual-change` действует без нового пуша, n4).
  Для `labeled`/`unlabeled` — условие `github.event.label.name == 'visual-change'` на job `baseline` (и через `needs`
  на `snapshots`): другие метки ничего не сравнивают (m-e). **Отмена — только между сравнивающими прогонами** (m-g):
  группа `concurrency` берётся при постановке прогона в очередь, до `if` job, поэтому прогон от посторонней метки
  получает **уникальную** группу и никого не отменяет: ключ `admin-visual-<номер PR или SHA>`, а для событий
  `labeled`/`unlabeled` с меткой не `visual-change` — тот же ключ плюс `-<run_id>`; `cancel-in-progress: true`.
  Итог: новый пуш или снятие/постановка `visual-change` отменяют прежнее сравнение этого PR; метка `docs` во время
  сравнения его не трогает (прогон метки — «skipped» в своей группе). `permissions: contents: read, actions: read,
  pull-requests: read`. Фильтр путей — шагом (ниже).
- **Два job** (m-d): в образе Playwright может не быть `git` и `gh` — тогда `actions/checkout` берёт дерево через REST
  без истории, и `HEAD^1`/`merge-base` падают. Поэтому:
  - **`baseline`** — на раннере `ubuntu-latest` (там есть `git` и `gh`): `actions/checkout` с `fetch-depth: 0`, база,
    фильтр путей, поиск эталона, проверка `expired`; выходы — `base`, `changed` (есть ли визуальные изменения),
    `run-id` эталона (пусто — эталона нет), `pr` (для `push`, m-f).
  - **`snapshots`** — `needs: baseline`, только если `changed`; `runs-on: ubuntu-latest`, **контейнер**
    `mcr.microsoft.com/playwright:v<версия @playwright/test>-noble` (сейчас 1.64.1; тег сверить при реализации) — шрифты,
    растеризатор и Chromium закреплены образом. Шаги: сборка витрины (`ladle build` или своя) и `admin:shots`-сборки →
    снимки набора → скачивание эталона по `run-id` (если есть) → сравнение. Историю git этому job не нужна.
- **Визуальные пути** (один список в скрипте `scripts/visual-baseline.mjs`): `apps/admin/src/**` (кроме `*.test.*`),
  `apps/admin/index.html`, `apps/admin/public/**`, `apps/admin/vite.config.ts`, `apps/admin/package.json`,
  `packages/tokens/**`, `packages/icons/**`, `contracts/tokens/**`, `pnpm-lock.yaml`, сам `admin-visual.yml` и конфиг
  снимков.
- **`push` в `main`** — снимки **всегда** (фильтра нет) → артефакт `visual-baseline-<sha>` (`actions/upload-artifact`,
  `retention-days: 90` — явно; по умолчанию GitHub хранит 90 дней, публичный репозиторий — от 1 до 90, приватный — до
  400; сверено 28.10.2026), в метаданных — версия образа Playwright. Тот же прогон сравнивает себя с предыдущим
  эталоном и пишет отличия в сводку (информативно), а если отличие есть, а у PR, принёсшего коммит (`gh api
  repos/{owner}/{repo}/commits/<sha>/pulls` → номер и метки), нет метки `visual-change` — ещё и аннотацию
  `::warning title=Вид изменён без метки::PR #<номер>: <число> отличий, отчёт — артефакт прогона` (m-f): при
  необязательной проверке это след регрессии, видимый в списке прогонов `main`. Аннотация на выбор эталона не влияет —
  эталоном служит любой прогон `main` с живым артефактом (по §5.3, п. 3).
- **`pull_request`**:
  Шаги 1–4 — job `baseline` на раннере, шаг 5 — job `snapshots` в контейнере (m-d).
  1. **База** — родитель merge-коммита: `git rev-parse HEAD^1` после `checkout` merge-ref (а не
     `pull_request.base.sha` события, который может отстать от того, с чем реально слит PR).
  2. Фильтр: `git diff --name-only <база> HEAD -- <визуальные пути>` пуст — job завершается зелёным пропуском.
  3. **Поиск эталона**: успешные прогоны **этого** workflow на `main`
     (`gh run list --workflow admin-visual.yml --branch main --event push --status success --json databaseId,headSha
     --limit 100`), от новых к старым; эталон — первый, чей `headSha` — предок базы
     (`git merge-base --is-ancestor <headSha> <база>`) и между ними нет изменений визуальных путей
     (`git diff --quiet <headSha> <база> -- <визуальные пути>`): картинка у него та же, что у базы, даже если база —
     коммит со спекой.
  4. Перед скачиванием — проверка артефакта: `gh api repos/{owner}/{repo}/actions/runs/<id>/artifacts` — есть и
     `expired: false` (иначе `download-artifact` падает, n4); затем `actions/download-artifact@v8` с `run-id` и
     `github-token`.
  5. Снимки PR → сравнение (`pixelmatch` в скрипте или `toHaveScreenshot` с подложенными эталонами) → при отличиях —
     job красный, артефакт отчёта «было / стало / разница» и список отличий в `GITHUB_STEP_SUMMARY`.
- **Намеренное изменение вида** — метка PR `visual-change`: сравнение идёт, отчёт-дифф прикладывается, но job не
  падает; ревьюер смотрит дифф глазами. После слияния `main` снимет новый эталон сам. Без метки любое отличие — красный.
- **Эталона нет** (первый прогон; ни один прогон `main` не подходит по п. 3; артефакт истёк) — сравнение
  **пропускается с предупреждением** в сводке («эталона нет: вид не сверен»), job зелёный; разошлись версии образа
  Playwright у эталона и PR — сравнение только информативное (отчёт без падения), иначе смена образа покраснила бы всё.
- **Обязательность** (решение контроллера 28.10): на старте проверка `admin-visual` **не обязательна** в защите ветки
  `main` — информирует и прикладывает дифф; красный результат — повод для ревьюера фронта (пункт чек-листа: «красный
  visual без метки — не одобрять»), но слиянию не мешает. **Перевод в обязательную**, когда выполнены все условия:
  ≥ 4 недели и ≥ 20 прогонов на PR с визуальными изменениями без ложных срабатываний (отличие не от PR — шрифт,
  сглаживание, гонка), доля «эталона нет» на таких PR < 10 %, job ≤ 12 минут. Шаг перевода: добавить `admin-visual` в
  обязательные проверки защиты `main` (настройки репозитория или `gh api … /branches/main/protection`), записать в
  `CLAUDE.md` и в журнал решений; job уже стартует на каждом PR (нет `paths`) и при отсутствии визуальных изменений
  зеленеет сам — PR не повиснет.
- **Стабильность:** `animations: 'disabled'`, `caret: 'hide'`, `reducedMotion: 'reduce'`, `timezoneId: 'UTC'`,
  `locale: 'ru-RU'`, `await document.fonts.ready` (шрифты — `@fontsource`, не системные), фиксированные даты и
  `useNow`; допуск — `maxDiffPixelRatio: 0.001` (сглаживание), не больше.
- **Локально сравнения нет**: конфиг пропускает тесты не на Linux (`test.skip(process.platform !== 'linux')` с
  понятным текстом) — шрифты Windows дали бы ложные отличия. В `./task ci` визуальный job не входит.

### 5.4. Скриншоты экранов для ревьюера

- Делается в **UF1a** (I11, n9): приёмка светлой палитры скриншотами (§2.4) нужна до слияния UF1b, а живой стек
  (Postgres, admin-api, вход с TOTP) для снимков тяжёл и невоспроизводим. Снимки «до» перекраски снимает **первый шаг
