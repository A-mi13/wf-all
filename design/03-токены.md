# Токены

Источник значений — `contracts/tokens/tokens.json` (сверено с артбордом «Токены»);
этот файл описывает имена и правила, а не окончательные числа.

Стартовый набор. Это не финальная палитра, а каркас: конкретные значения
подбираются в дизайне, но структура и имена должны остаться — по ним потом
генерятся переменные для Next.js, Flutter и админки.

Правило одно: ни одного цвета и отступа мимо токенов. Полноценная дизайн-система
сейчас преждевременна, но токены нужны сразу, иначе три клиента разъедутся.

## Цвет

Семантические имена, не «зелёный». Две темы — тёмная и светлая (по умолчанию — системная); прежние тёмные
значения не менялись (P21), светлые — пары к ним (раздел «Темы» ниже).

```
--bg              фон приложения
--bg-elevated     карточка, шит
--bg-sunken       поле ввода, вдавленный блок
--border
--border-strong

--text            основной
--text-muted      второстепенный
--text-inverse    на акцентной заливке

--accent          единственный яркий цвет, один на весь продукт
--accent-hover
--accent-muted    фон чипа, полосы прогресса

--success         состав собран, оплачено
--warning         мало времени, мало людей
--danger          отмена, неявка, бан
--info

--pitch           заливка схемы поля
--pitch-line      разметка
--slot-empty      свободная позиция
--slot-filled     занятая позиция
```

Акцент один. Соблазн раскрасить формат матча в разные цвета нужно задавить:
на ленте из двадцати карточек это превращается в кашу.

### Админка (макеты 07, 08)

Добавлены к общим токенам, прежние не меняются (`text-subtle`, `text-disabled` остались как были):

```
--color-surface-sunken   сайдбар, таббар, поля ввода, ячейки кода
--color-chip-bg          нейтральный чип, счётчик
--color-chip-accent-bg   активный чип и счётчик, роль «админ»
--color-success-bg       фон статуса и тоста «успех»
--color-warning-bg       фон предупреждения
--color-danger-bg        фон ошибки, опасного действия
--color-danger-border    рамка ошибки и опасной кнопки
--color-text-faint       только значки (контраст < 4.5:1); плейсхолдеры — text-subtle
--color-text-ghost       только недоступное (disabled) и декоративное
--breakpoint-mobile      768 — ширина переключения раскладки: уже — нижний таббар
```

Подписи и плейсхолдеры — `text-subtle`, не `text-faint`; подписи на чипах (`chip-bg`) — `text-muted`
(`text-subtle` на `chip-bg` не проходит 4.5:1 и запрещён стражем). В `@media` CSS-переменные не работают:
ширину берёт JS из `@wf/tokens` (`tokens.breakpoint.mobile`).

## Темы (спека UI-фундамента §2; UF1b)

**Формат цвета в `tokens.json`** — контракт между репо (веб, админка, Flutter в wf-native); меняется только с
записью здесь:
- строка `"#RRGGBB"` или `"#RRGGBBAA"` — одно значение на обе темы (`accent`, `text-inverse`);
- объект `{ "dark": "#…", "light": "#…" }` — пара (оба ключа обязательны).
- `#RRGGBBAA` — альфа последним байтом (`scrim`, цвет теней); Flutter читает его как ARGB (`0xAARRGGBB`).

Генерация (`packages/tokens/scripts/build.mjs`): пара → `light-dark(<светлое>, <тёмное>)`, строка — как есть;
`:root { color-scheme: dark }` (без атрибута — тёмная), `:root[data-theme='light'] { color-scheme: light }`,
`:root[data-theme='system'] { color-scheme: light dark }`. Атрибут `data-theme` ставит только админка
(`public/theme-init.js` до первого кадра, переключатель «Система · Светлая · Тёмная»). **Веб** атрибут не ставит и
остаётся тёмным: Next 16 (Turbopack, Lightning CSS, цели по умолчанию Chrome 111 / Safari 16.4) полифилит
`light-dark()` и в dev, и в сборке — полифил работает, потому что `color-scheme` объявлен в том же `tokens.css`.
При переводе веба на две темы — свои цели браузеров веба или осознанный полифил. Админка полифила не допускает:
`build.cssTarget` (Chrome 123, Firefox 125, Safari/iOS 17.5) и проверка `dist` в `admin:ci`. JS, которому нужен
цвет текущей темы, берёт его из `tokens.ts` (`tokens.color.<имя>[тема]`, в админке — `useThemeColors()`), а не
`getComputedStyle` (он вернул бы строку `light-dark(…)`).

**Роли «чернила / заливка»** (§2.3): яркий акцент на светлом фоне нечитаем текстом, поэтому:

```
--color-accent           только заливка: основная кнопка, включённый переключатель, полоса меню
--color-accent-ink       текст, линия, курсор, акцент значка (в тёмной = accent, в светлой #3B6600)
--color-accent-detail    деталь/тень акцента значка — темнее акцента в обеих темах
--color-focus            кольцо фокуса
--color-border-control   рамка поля ввода (≥ 3:1 к фону)
--color-selected-border  рамка выбранного сегмента и выбранного чипа таблицы: тёмная #2C4434 (рамка
                         выбранного артборда 07), светлая = accent-ink (3:1 к surface-sunken, bg и pitch);
                         включённый Switch — accent-ink
--color-danger-fill      заливка опасной кнопки, на ней — --color-text-on-danger
--color-scrim            затемнение под оверлеем (#RRGGBBAA)
--color-qr-ink / -paper  QR — своя светлая плашка в обеих темах
```

**Контраст** (WCAG 2.2 AA, таблица — спека §2.6): пары «текст × фон» — массив `contrast` в `tokens.json`,
строка `["<текст>", "<фон>", <норма>]`. Норма — число (обе темы: 4.5 — текст, 3 — значки, рамки, крупное) или
объект `{ "dark"?: <число>, "light"?: <число> }` — только для названных тем (`selected-border` — `{ "light": 3 }`:
в тёмной рамка декоративная, как в артборде). Стражи: `packages/tokens/test/contrast.test.mjs` (каждая строка — в
своих темах), `apps/admin/src/ui/contrast-css.test.ts` (каждая пара из CSS Modules есть в `contrast`; строка с
нормой-объектом текстом в обеих темах не годится). Цвета с альфой (`scrim`, тени) в `contrast` не входят.
Генератор Flutter строит из `contrast` свой страж на тех же парах.

**Тени — данными**: `shadow.<имя>: { "y", "blur", "color": <цвет или пара> }` → `--wf-shadow-<имя>: 0 <y>px
<blur>px light-dark(…)` (`light-dark()` принимает только цвета — геометрия снаружи); Flutter → `BoxShadow`.
Сейчас: `overlay` (24/64), `toast` (16/40).

**Плотность, контейнеры, переломы**: `density.compact.row` 36 / `density.normal.row` 48 (строка таблицы);
`container.narrow` 480 (панель), `container.wide` 720 — пороги `@container`; `breakpoint.compact` 1024 (полоса
768–1023, свёрнутое меню). Размеры каркаса — `size.sidebar` 236, `rail` 64, `palette` 640, `tabbar`,
`table-header`, `toast`.

## Типографика

Два шрифта: Oswald — крупные цифры и заголовки, Manrope — текст; оба с кириллицей.
Цифры табличные (`tabular-nums`) — иначе счёт и статистика будут прыгать.

```
--font-display    крупные цифры: счёт, статистика, места в таблице
--font-body

--text-3xl   32 / 36   счёт матча, число в карточке игрока
--text-2xl   24 / 30   заголовок экрана
--text-xl    20 / 28   название команды, матча
--text-lg    18 / 26
--text-base  16 / 24   основной
--text-sm    14 / 20   подписи, метаданные
--text-xs    12 / 16   бейджи
```

Меньше 12 не опускаться: экран читают на улице.

## Отступы

Шаг 4. Ничего мимо шкалы.

```
--space-1   4      --space-6   24
--space-2   8      --space-8   32
--space-3   12     --space-10  40
--space-4   16     --space-12  48
--space-5   20     --space-16  64
```

Боковое поле экрана — 16. Внутренний отступ карточки — 16, между карточками — 12.

## Радиусы и тени

```
--radius-sm    8     чип, бейдж
--radius-md    12    поле ввода, кнопка
--radius-lg    16    карточка
--radius-xl    24    шит снизу
--radius-full        аватар, круглая кнопка

--shadow-card
--shadow-sheet
```

В тёмной теме тени почти не работают — разделяй слои фоном (`--bg-elevated`),
а не тенью.

## Движение

```
--duration-fast    120ms   нажатие, переключатель
--duration-base    200ms   появление шита, переход
--duration-slow    400ms   разворот карточки лидера
--ease             cubic-bezier(0.2, 0, 0, 1)
--ease-exit        cubic-bezier(0.3, 0, 1, 1)   уход: панель, тост
```

Анимации две и обе осмысленные: заполнение полосы состава и разворот карточки
первого места в таблице. Остальное — мгновенное. Уважай
`prefers-reduced-motion`: `tokens.css` обнуляет все `--wf-duration-*` в `@media (prefers-reduced-motion: reduce)`.
Смена темы — мгновенно, без анимации.

## Что описать компонентами

Кнопка (основная, вторичная, опасная, отключённая), поле ввода с ошибкой,
чип фильтра, карточка матча, карточка команды, аватар с рамкой, бейдж
(тип матча, возраст, новичок), полоса прогресса, пустое состояние с иллюстрацией,
шит снизу, кружок позиции на схеме поля в трёх состояниях: свободен,
занят, забронирован.
